# 2. Системный планировщик

## Типы операционных систем
**Многозадачность** - возможность ОС выполнять параллельно или псевдопараллельно несколько процессов.

**Кооперативная многозадачность** - процесс не прерывается принудительно, процесс сам знает, когда нужно прервать свое выполнение. Плохо, так как планировщик не может управлять процессами, и в теории процесс может монополизировать все процессорное время.

**Вытесняющая многозадачность** - системный планировщик самостоятельно принимает решение о том, в какой момент времени следует прекратить выполнение текущего процесса и переключиться на выполнение другого процесса.

## Планировщик Linux

Обьект планировщика: 
```cpp
struct sched_entity {
    struct load_weight load;
    struct rb_node run_node;
    struct list_head group_node;
    unsigned int on_rq;
    u64 exec_start;
    u64 sum_exec_runtime;
    u64 vruntime;
    u64 prev_sum_exec_runtime;
    u64 last_wakeup;
    u64 avg_overlap;
    u64 nr_migrations;
    u64 start_runtime;
    u64 avg_wakeup;
    /* Множество переменных stat опущено, они появляются, только
    если установлен параметр конфигурации CONFIG_SCHEDSTATS */
};
```

Все процессы можно разделить на процессы реального времени (интерактивные процессы, где время отклика критично, например операции ввода-вывода) и условные процессы (активно использующие CPU). В `sched_entity` может быть несколько политик планирования одновременно.

У каждого типа процессов есть свой алгоритм планирования. При этом пока есть готовые к выполнению процессы реального времени, выполняться будут они, оставляя условные процессы в ожидании.

## Планирование процессов реального времени:
Используются две политики: `SCHED_RR` и `SCHED_FIFO`.

В стратегии `SCHED_FIFO` реализован простой алгоритм планирования по принципу “первым пришел — первым обслужен” **без использования квантов времени**. Готовая к выполнению задача со стратегий `SCHED_FIFO` будет всегда планироваться на выполнение перед всеми другими заданиями со стратегией планирования `SCHED_NORMAL`. Когда задача со стратегией `SCHED_FIFO` становится готовой к выполнению, она будет выполняться до тех пор, пока не будет заморожена или пока явно не отдаст управление другой задаче. Поскольку кванты времени при этом не используются, задача может выполняться бесконечно долго. Ее может вытеснить только задача с более высоким приоритетом, которая планируется по стратегии `SCHED_FIFO` или `SCHED_RR`.

Стратегия планирования `SCHED_RR` идентична `SCHED_FIFO` за исключением того, то каждый процесс может выполняться до момента исчерпания выделенного кванта времени процессора. Другими словами, `SCHED_RR` — это `SCHED_FIFO` с квантованием, или циклический (round-robin) алгоритм планирования задач реального времени. Как только квант времени, выделенный задаче `SCHED_RR`, будет исчерпан, все остальные задачи реального времени с одинаковым приоритетом планируются по циклическому алгоритму. Здесь квант времени используется только для того, чтобы перепланировать остальные задачи с одинаковым приоритетом. Так же как в случае стратегии `SCHED_FIFO`, процесс с более высоким приоритетом сразу же вытесняет процессы с более низким приоритетом, а процесс с более низким приоритетом никогда не сможет вытеснить процесс со стратегией планирования `SCHED_RR`, даже если у последнего исчерпался квант времени.

Для задач реального времени приоритет: [0, MAX_RT_PRIO - 1], где обычно MAX_RT_PRIO = 100.


## Планирование условных процессов: SCHED_NORMAL.

Тут используется `CFS` - полностью справедливый планировщик. Он стремится к максимальной равноправности процессов, то есть обеспечивает выделение всем процессам равных квантов времени CPU. Но процессы с повышенным приоритетом все равно могут получать на обработку больше времени.

Для выбора следующего процесса на выполнение используется `vruntime` - Виртуальное время выполнения процесса – это количество времени, потраченного именно на выполнение, без учета любых ожиданий.
CFS выбирает следующую задачу на выполнение по минимальному `vruntime`.
CFS задействует красно-черное дерево, представляющее бинарное дерево поиска – то есть добавление, удаление и поиск выполняются за `O(logN)`. Новые процессы или процесс, возвращающиеся из ожидания в состояние готовности, добавляются в дерево с ключом vruntime = `min_vruntime`.

В первую очередь он устанавливает себе лимит времени – `sched_latency`.
В течение этого времени алгоритм стремится выполнить все готовые процессы – N. Это означает, что каждый процесс получит интервал времени равный временному лимиту, поделенному на количество процессов: `Qi = sched_latency/N.`
Когда процесс исчерпывает свой интервал (`Qi`), алгоритм выбирает в дереве следующий процесс с наименьшим виртуальным временем.
Если задач слишком много, то в данном случае переключение контескта может занимать большую долю из `Qi`. Для этого вводится минимальная протяженность кванта времени выполнения – `min_granularity`.
Он и подправляет значение `sched_latency`.

## Работа с планировщиком

schedule() запускает системный планировщик. Внутри вызывается функция pick_next_task(), которая обходит все классы планировщика, начиная с самого высокоприоритетного и выбирает самый высокоприоритетный процесс и возвращает его.

## Вытеснение и переключение контекста

Под переключением контекста будем понимать переход от одной выполняемой задачи к другой, который осуществляется с помощью функции `context_switch()`.  Эта функция вызывается из функции `schedule()` после выбора нового процесса, который должен быть запущен. В ней выполняются два важных шага:
1. Вызывается функция `switch_mm()`. Она выполняет переход от виртуальной памяти старого процесса к виртуальной памяти нового процесса.
2. Вызывается функция `switch_to()`, которая переключает состояние процессора от старой задачи к новой. Эта процедура включает сохранение и восстановление информации стека ядра и регистров процессора, а также любого другого состояния, которое зависит от применяемой аппаратной платформы и должно выполняться для каждого процесса.

> При смене задачи происходит очистка TLB (чтобы для последующего использования не было много missов, TLB для определенного процесса сохраняется в памяти процесса)
