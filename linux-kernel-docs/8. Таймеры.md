# 8. Таймеры
   
## Таймеры в ядре

_Системный таймер_ - отвечает за генерацию переодически происходящих событий - аппаратное устройство, основой которого является кварцевый генератор, которое генерирует аппаратные прерывания с заданной частотой. В этом прерывании обновляется значение системного времени и выполняется периодические действия. 

_Динамический таймер_ - позволяет планировать события, которые выполняются один раз, после истечения некоторого интервала времени. Например, такой таймер используется в драйвере накопителя на гибких магнитных дисках для остановки двигателя привода, если тот не используется в течение некоторого периода времени. Подобные таймеры создаются
и аннулируются в ядре динамически, по мере необходимости.

Задачи, которые решаются в обработчике прерывания системного таймера:
1. Обновление времени непрерывной работы системы (время, прошедшее с последней перезагрузки системы).
2. Обновление абсолютного времени.
3. Для SMP систем проверка сбалансированности очередей выполнения планировщика. Есть очередь задач, готовых к выполнению на CPU0 больше чем на CPU1, то балансировка

Частота системного таймера определяется через дефайн `HZ`. Обычно он равен 1000. `HZ` раз в секунду происходит прерывание от системного таймера.
Плюсы бОльшего значения HZ:

1. Чем больше данное значение, тем большая разрешающая способность системы(работа будет выполняться чаще).
2. Более точное измерение времени (погрешность - HZ / 2).
3. Более корректное вытеснение задач. Если оставшееся процессорное время для задачи равно 1мс, то только через ~10мс (HZ = 100) новая задача будет запущена, все остальное время будет простой.

Минусы бОльшего значения HZ:
1. Так как прерываний в единицу времени становится больше, то тратится больше времени на выполнение кода обработчика прерывания. Кроме того возрастает количество сохранений контекста, очистка кэша, рост потребляемой мощности - падение производительности.

Возможна также динамическая настройка HZ. Если установить CONFIG_HZ, то система будет динамически управлять прерываниями от таймера. Поэтому если система простаивает, то и снижается потребляемая мощность.

## jiffies

В глобальной переменной `jiffies` содержится количество импульсов системного таймера, которые были получены со времени загрузки системы. Во время начальной загрузки ядро обнуляет значение этого параметра; при каждом прерывании системного таймера он будет увеличиваться на единицу.

Таким образом, время непрерывной работы системы (uptime) равно `jiffies/HZ` секунд. 



Определение глобальной переменной:
```c
extern unsigned long volatile jiffies;
```

## Аппаратные часы и таймеры

Для упрощения отсчета времени на всех поддерживаемых компьютерных платформах предусмотрены два аппаратных устройства — системный таймер и часы реального времени.

_Часы реального времени_ (real-time clock, RTC) представляют собой энергонезависимое устройство, в котором хранится системное время. Устройство RTC продолжает отслеживать ход времени, даже когда компьютер обесточен, благодаря небольшой батарейке, которая обычно находится на системной плате. При выполнении начальной загрузки ядро считывает информацию из устройства RTC и использует ее для инициализации значения абсолютного времени, которое хранится в переменной xtime.

_Системный таймер_ играет самую важную роль в процессе отслеживания хода времени в ядре и чаще всего используется для этой цели. Независимо от используемой аппаратной платформы идея, лежащая в основе работы системного таймера, всегда одна и та же — обеспечение механизма управления прерываниями, возникающими периодически
с постоянной частотой.

Обработчик прерываний от системного таймера состоит из двух частей: аппаратно-зависимой и аппаратно-независимой.

### Что там происходит?
1. Захватывается блокировка `xtime_lock`, которая закрывает доступ к переменной `jiffies_64` и значению текущего времени — переменной `xtime` — со стороны других процессов.
2. Считывается или сбрасывается состояние системного таймера, если это необходимо.
3. Периодически записывается новое значение абсолютного времени в CMOS-память часов реального времени.
4. Вызывается аппаратно-независимая функция таймера `tick_periodic()`:
   1. Значение переменной `jiffies_64` увеличивается на единицу.
   2. Для выполняющегося в данный момент процесса обновляется статистка использования системных ресурсов, таких как процессорное время, затраченное на выполнение кода ядра и кода пользовательского приложения.
   3. Выполняются обработчики динамических таймеров, для которых истек период времени ожидания
   4. Вызывается функция `scheduler_tick()` - уменьшает значение кванта времени для текущего выполняющегося процесса и по необходимости устанавливает флаг `need_resched`. Для SMP-машин в этой функции также, если нужно, выполняется балансировка очередей выполнения.
   5. Обновляется значение абсолютного времени, которое хранится в переменной `xtime`.
   6. Вычисляется значение показателя средней загруженности системы (load average).

## Динамические таймеры
Динамические таймеры необходимы для управления ходом времени в ядре, так как в коде ядра часто необходимо отложить выполнение некоторых функций на более позднее время.
Таймеры не являются циклическими. Когда заканчивается интервал времени ожидания, таймер аннулируется. Это одна из причин, почему таймеры называют динамическими. Таймеры постоянно создаются и аннулируются, на количество создаваемых таймеров не накладывается никаких ограничений.

Таймеры представляются структурой `timer_list`:
```c
struct timer_list {
   struct list_head entry; /* Элемент связанного списка таймеров */
   unsigned long expires; /* Время окончания срока ожидания в импульсах системного таймера (jiffies) */
   void (*function)(unsigned long); /* Функция-обработчик таймера */
   unsigned long data; /* Единственный аргумент, передающийся обработчику */
   struct tvec_t_base_s *base; /* Внутренние данные таймера, не трогать! */
};
```

Перед использованием таймера его нужно объявить:
```c
struct timer_list my_timer;
```
Инициализация таймера:
```c
init_timer(&my_timer);
```

Далее необходимо заполнить все поля таймера:
```c
my_timer.expires = jiffies + delay;
my_timer.data = data;
my_timer.function = my_function;
```

Последняя операция — это запуск таймера:
```c
add_timer(&my_timer);
```

Изменить момент времени срабатывания таймера, который уже запущен:
```c
mod_timer(&my_timer, jiffies + new_delay);
```

Если нужно остановить таймер до момента его срабатывания, используется функция:
```c
del_timer(&my_timer);
```
