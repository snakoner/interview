# 12. Страничный кеш

В ядре Linux реализована дисковая кеш-память, которая называется страничным кешем (page cache). Он предназначен для уменьшения количества
дисковых операций ввода-вывода за счет хранения часто используемых данных в оперативной памяти компьютера.

## Причины введения page cache
1. Доступ к данным, хранящимся на диске(миллисекунды), на несколько порядков медленее, чем к данным в оперативной памяти(наносекунды).
2. Временная локализация - если к данным осуществляется доступ, то с большой вероятностью к этим же данные будет обращение снова.

## Методики кеширования
Страничный кеш состоит из страниц физической памяти, содержимое которых соответствует физическим блокам на диске. Размер страничного кеша может динамически
изменяться. _При наличии свободной памяти он увеличивается, а при недостатке физической памяти — уменьшается_.

Например, при вызове `read()` ядро сначала проверяет, нет ли запрашиваемого файла в page cache. Если есть (cache hit), то данные копируются прямо из оперативной памяти. Если нужных данных в page cache нет, то инициируются операции блочного доступа, данные читаются и помещаются в page cache. 

Обычно полной копии файла в памяти нет - копируются только те страницы файла, к которым осуществляется доступ.

### No write (без кеширования)

В данной стратегии при записи в файл данные не кешируются в page cache, а сразу записываются на диск. При этом в page cache данные помечаются как недействительные. Такая стратегия используется редко.

### Write through (сквозная запись)

В данной стратегии данные обновляются в page cache и сразу же записываются на диск. Таким образом, данные и page cache и на диске находятся в согласованном состоянии.

### Write back (отложенная запись)

При записи данные помещаются в page cache, но запись на диск сразу же не выполняется. Вместо этого страница помечается как `dirty` и помещается в список `dirty_list`. Потом специальный процесс `write-back`, который периодически планируется и выполняет запись на диск. После этого страница становится не `dirty`. 

Данная стратегия применяется чаще всего.

## Вытеснение данных из кеша

Данные из кеша могут вытесняться в случае:
1. Нехватка оперативной памяти
2. Освобождение памяти под более подходящие данные.

### Стратегия минимального использования

Применяется алгоритм LRU(least recently used) - вытеснение страницы с наиболее старым временем последнего обращения. Возможные реализации: каждой странице соответствует временная метка, либо все страницы упорядочены по времени последнего обращения.

Недостаток стратегии: при однократном доступе к файлу алгоритм работает плохо.

### Стратегия с двумя списками

Модифицированный LRU, называется LRU/2. Здесь используются два списка: `active` и `passive`: страницы из active рассматриваются как нужные, страницы из `passive` могут быть вытеснены на диск. В список `active` страницы попадают только в том случае, если они находятся в `passive` списке. Таким образом, если производится первое обращение к странице на диске, то такая страница попадает в `passive` и является кандидатом на вытеснение. Причем элементы вытесняются из начала списка(как в очереди), а новые помещаются в конец.

Размеры `active` и `passive` поддерживаются примерно одинаковыми: если `active` слишком большой, часть его элементов из начала переносится в конец `passive`. 

## Реализация page cache в Linux

Запись в page cache определяется структурой `address_space`:

```cpp
struct address_space {
  struct inode *host; /* Файловый индекс, которому
  принадлежит объект */
  struct radix_tree_root page_tree; /* Базисное дерево всех страниц */
  spinlock_t tree_lock; /* Блокировка для защиты дерева страниц */
  unsigned int i_mmap_writable; /* Количество областей памяти
  с флагом VM_SHARED */
  struct prio_tree_root i_mmap; /* Список всех отображений */
  struct list_head i_mmap_nonlinear;/* Список областей памяти
  с флагом VM_NONLINEAR */
  spinlock_t i_mmap_lock; /* Блокировка поля i_mmap */
  atomic_t truncate_count; /* Счетчик запросов truncate */
  unsigned long nrpages; /* Общее количество страниц */
  pgoff_t writeback_index; /* Смещение начала отложенной записи */
  struct address_space_operations *a_ops; /* Таблица операций */
  unsigned long flags; /* Маска gfp_mask и флаги ошибок */
  struct backing_dev_info *backing_dev_info; /* Информация для
  упреждающего чтения */
  spinlock_t private_lock; /* Блокировка для частных отображений */
  struct list_head private_list; /* Список частных отображений */
  struct address_space *assoc_mapping; /* Связанные буферы */
};
```
Поле i_mmap - список всех отображений данного файла (отображение mmap, но всем mmap соответствует единственный address_space).
Поле nrpages - количество страниц, которые описывает address_space


Структура address_space_operations описывает основные операции ввода-вывода. Для каждого вида файловой системы(например ext3) - свои указатели. Наиболее важные функции:
1. read_page()
2. write_page()

Перед чтением/записью какой-либо страницы, ядро сначала проверяет наличие в page cache.
