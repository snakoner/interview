# 5. Прерывания и их обработка

Прерывания позволяют аппаратным устройствам послать сигнал процессору (например, при нажатии кнопки). При этом устройство генерирует специальный электрический сигнал(выставляет высокое напряжение на линии).
```cpp
[Device 1] ---0--->  |---------------|                       |--------------|
[Device 2] ---1--->  |  Interrupt    | ----Interrupt Code--> |              | ---> handlerN()
...                  |  Controller   |                       |     CPU      |
[Device N] ---0--->  |_______________|                       |______________|
```

Сигналы прерывания, поступающие от устройств, часто называют линиями запросов на прерывание (_interrupt request lines_, IRQ). Каждой линии IRQ назначается соответствующий номер, который является восьмиразрядным двоичным числом.

> Исключительные ситуации (_exceptions_) часто описываются вместе с прерываниями. В отличие от прерываний, они возникают синхронно с тактовым генератором процессора. И действительно, их часто называют синхронными прерываниями (_synchronous interrupts_). Исключительные ситуации генерируются самим процессором при выполнении машинных команд как реакция на ошибку в программе(например, деление на нуль) или как реакция на аварийную ситуацию, которая должна быть обработана ядром (например, прерывание из-за отсутствия страницы (page fault)). Так как на большинстве аппаратных платформ исключительные ситуации обрабатываются аналогично обработке прерываний, инфраструктуры ядра для обоих видов обработки также аналогичны.

## Обработчики прерываний
Функция, которую запускает ядро в ответ на поступление сигнала определенного прерывания, называется обработчиком прерывания (_interrupt handler_), или программой
обслуживания прерывания (_interrupt service routine_). Каждому устройству, которое может генерировать прерывания, в ядре соответствует свой обработчик прерывания. Обработчик прерывания для определенного устройства является частью драйвера этого устройства — кода ядра, который управляет
устройством.

Обработчики прерывания всегда выполняются в специальном контексте - **контексте прерывания**: код, выполняющийся в нем не может переходить в состояние ожидания.

Обработчик прерывания выполняется при: 
1. Всегда: отключенной линии прерывания текущего прерывания для всех процессоров.
2. Не всегда: отключаются все прерывания на процессоре, выполняющем текущее прерывание, если обработчик регистрировался с IRQF_DISABLED.

Поэтому обработчик прерывания может быть прерван на текущем процессоре другим обработчиком, но не тем же.

## Верхняя и нижняя половины

Так как прерывание может возникнуть в любой момент времени, то обработчик прерывания должен выполняться быстро. В связи с этим обработка прерываний зачастую разбивается на две половины - **верхняя половина**, в который выполняется сам обработчик прерывания, и **нижняя половина**, код которой может быть выполнен позже.

## Регистрация обработчика прерывания

Обработчик прерывания является часть драйвера устройства.

Зарегистрировать обработчик прерывания в ядре можно следующим образом:

```cpp
request_irq(unsigned int irq,        /* номер линии прерывания, в зависимости от аппаратной реализации
                                        может быть жестко задан, а может быть выделен динамически ядром Linux  */
              irq_handler_t handler,    /* указатель на функцию обработчик */
              unsigned long flags,     /* флаг обработчика */
              const char *name,        /* имя устройства, связаного с данным обработчиком */
              void *dev                /* структура устройства, используется в самом обработчике для получения данных и для различения различных обработчиков одной линии */
)
```

### Флаги обработчика прерываний

Параметр flags может быть равен 0 или содержать битовую маску следующих флагов:
1. IRQF_DISABLED - во время выполнения данного обработчика все остальные прерывания запрещены.
2. IRQF_TIMER - данный обработчик обслуживает системный таймер.
3. IRQF_SHARED - данный номер IRQ может совместно использоваться несколькими обработчиками прерываний (то есть несколькими устройствами). Каждый из обработчиков будет выполняться последовательно до тех пор, пока не будет найдено нужное устройство: это выясняется внутри обработчика прерывания, например с помощью регистра статуса.

## Освобождение обработчика прерывания

Чтобы удалить обработчик прерывания:
```cpp
void free_irq(unsigned int irq, void *dev)  // с помощью dev ядро понимает, какой обработчик удалить, если он не единственный для линии irq.
```

При этом, если данный обработчик - единственный, который обслуживает данную линию, то линия блокируется - ядро не обрабатывает прерывание с этим номером. Иначе, в случае совместного использования, линия заблокируется только тогда, когда будет удален последний обработчик для данной линии. 

> Обработчики прерываний в операционной системе Linux не обязательно должны быть реентерабельными (повторно входимыми). Когда выполняется некоторый обработчик прерывания, соответствующая линия запроса на прерывание маскируется на всех процессорах, что предотвращает возможность приема другого запроса на прерывание с этой линии IRQ. Обычно все остальные прерывания в этот момент разрешены, поэтому другие прерывания могут обслуживаться, тогда как текущая линия IRQ всегда замаскирована. Следовательно, никакой обработчик прерывания никогда не может быть вызван параллельно самому себе для обработки вложенных запросов на прерывание. Данный факт позволяет значительно упростить написание обработчиков прерываний.

В случае совместно используемых прерывания: когда ядро получает запрос на прерывание, оно последовательно вызывает все обработчики, зарегистрированные для данной линии IRQ. Поэтому важно, чтобы обработчик прерывания был в состоянии определить, какое устройство является источником этого прерывания.

## Контекст прерывания


В отличие от контекста процесса контекст прерывания не связан ни с одним процессом. Поэтому макрос current не имеет особого смысла, хотя он и возвращает указатель на процесс, выполнение которого было прервано. Поскольку в контексте прерывания нет сопровождающего его процесса, этот контекст нельзя перевести в состояние ожидания. Дело в том, что тогда нарушилась бы работа системного планировщика: нельзя перепланировать контекст, в котором нет задачи. Поэтому некоторые функции ядра не могут быть вызваны из контекста прерывания. Если функция может переводить процесс в состояние ожидания, то ее нельзя вызывать в обработчике прерывания, а это, в свою очередь, ограничивает набор функций, которые можно использовать в обработчиках прерываний.

Также нежелательно использование busy loop.  

Раньше у прерываний не было своего стека. Он использовали стек ядра прерванного процесса (его размер 2 страницы). 
Сейчас **у каждого обработчика прерывания есть твой стек**, который называется _стеком прерывания_, причем этот **стек свой для каждого ядра**. Его размер - 1 страница.

## Как происходит прерывание в ядре

1. Устройство инициирует прерывание путем отправки электрического сигнала контроллеру прерываний по аппаратной шине.
2. Если данная линия в контроллере не запрещена, IC отправляет сигнал CPU.
3. Если прерывания в CPU разрешены, то CPU запрещает любые новые прерывания и прерывает выполнение текущего процесса и прыгает на предопределенный адрес - точка входа в обработчик.
4. Ядро переходит в режим ядра (например M для RISC-V). Это происходит через обработчик исключительных ситуаций.
5. Ядро сохраняет номер прерывания и все регистры процессора, которые относились к выполнению прерванной задачи.
6. Ядро выполняет `do_IRQ()` - проверка, что для текущего номера прерывания определен обработчик, что он не запрещен и что он не выполняется в текущий момент.
7. Если предыдущие условия не выполнены, то происходит проверка: есть ли новый процесс на планирование, восстанавливается контекст.
8. Если выполнены, то исполняется обработчик прерывания и те же действия, что и в предыдущем пункте.

## Запрещение и разрешение прерываний

Запретить/разрешить все прерывания на текущем процессоре:
```cpp
local_irq_disable();
local_irq_enable();
```

Запретить/разрешить прерывание с определенным номером на всех процессорах:
```cpp
void disable_irq(unsigned int irq);          // запретить номер для всех процессоров
void disable_irq_nosync(unsigned int irq);  // не ждет, пока текущий обработчик прерывания(если выполняется) закончил выполнение
void enable_irq(unsigned int irq);          // разрешить прерывания
void synchronize_irq(unsigned int irq);    // ожидает, пока указанный обработчик прерывания завершит свою работу, если он, конечно, был запущен.
```
