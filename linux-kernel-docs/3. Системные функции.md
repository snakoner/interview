# 3. Системные функции

В ядре любой современной ОС предусмотрен ограниченный набор интерфейсов, с помощью которых пользовательская программа может взаимодействовать с аппаратной системой. 

Примеры системных функций в userspace:
> open, close, read, write, exit, fork, chdir, mkdir, ioctl

## Зачем нужны syscalls?
Системные функции - прослойка между пользовательскими процессами и оборудованием компьютера. Их задачи:
1. Обеспечивают абстрактный интерфейс для взаимодействия. Например, при чтении файла с диска процессу не важно, на каком диске расположен файл и какая FS на данном диске.
2. Гарантия безопасности и стабильности ОС - возможность ядру ОС принимать решение о предоставлении доступа процессу к какому-либо ресурсу системы.

Благодаря системных функциям можно сделать многозадачность и виртуальную память - если бы процесс имел доступ ко всем ресурсам системы, то было бы невозможно реализовать многозадачность и виртуальную память.

> Важно: системные функции могут прерываться

## API, POSIX и библиотека C

Явное использование syscall в пользовательских программах довольно редки - для этого существует набор функций, входящих в API. Эти функции могут быть реализованы с помощью вызова одной или нескольких syscall. 

Например мы хотим вызвать printf():

Один из самых популярных программных интерфейсов приложений в мире Unix-подобных операционных систем основан на стандарте POSIX. Нужен для переносимости ПО. Основной набор правил POSIX:

1. Разграничение прав пользователей и групп, а также суперпользователя root с привилегированными правами; 
2. Наличие древовидной файловой системы, которая имеет единый корень /; 
3. Система и программные пакеты предоставляются в виде текстовых файлов – то есть, конфигурации файлов можно изменить простым редактированием; 
4. **Единый API программирования языка C**
5. Единый стандарт консольных утилита и команд

## Системные функции

Syscalls обычно не вызываются напрямую, вместо них вызываются функции-обертки из стандартной библиотеки языка C. Им могут передаваться аргументы. 
Возвращают `long`, обычно 0 при успешном завершении syscall и отрицательное значение при ошибке. Кроме того, код ошибки записывается в глобальную переменную `errno`. Преобразовать данный код в строку можно с помощью функции `perror`.

## Номера системных функций

В системе Linux каждой системной функции присвоен специальный номер (`syscall number`). Этот уникальный номер используется для обращения к нужной системной функции. Когда пользовательской программе нужно вызвать ту или иную системную функцию, она использует для этой цели соответствующий номер, а не имя системной функции.

Номер системной функции является важным атрибутом. После того как он будет назначен системной функции, его уже нельзя изменять(в realtime), поскольку это нарушит работу уже скомпилированных прикладных программ. Более того, если системная функция будет удалена из ядра, то соответствующий номер нельзя использовать повторно для другой
функции.

Список всех зарегистрированных системных функций хранится в ядре в `специальной таблице`, адрес которой находится в переменной `sys_call_table`. Формат данной
таблицы зависит от используемой аппаратной платформы. Для платформы x86-64 он определен в файле arch/i386/kernel/syscall_64.c. С помощью этой таблицы каждому уникальному номеру системной функции сопоставляется адрес реальной системной функции.

## Обработчик вызова системных функций

![image info](https://imgbly.com/ib/Cokl8uOArY.png)

При вызове системной функции возникает exception(с помощью специальной ассемблерной команды, например ecall в riscv), система переключается в режим ядра и запускается специальный обработчик `system_call()`. Для данного обработчика в каждой аппаратной платформе зарезервирован специальный номер прерывания. 

Номер системной функции передается в обработчик с помощью регистра, а в данном обработчике значение считывается. Далее проверяется, зарегестрирована ли системная функция с таким номером, если нет - возвращается `-ENOSYS`. Если такая функция есть, то она вызывается.

Кроме того, бывает необходимо передать параметры для syscall. Параметры передаются с помощью регистров. Если параметров слишком много, то в один из регистров можно записать адрес блока параметров(указатель на структуру) в пространстве пользователя. Возвращаемое значение также передается пользователю через регистры.

## Реализация системных функций

Любой пользователь может создать свою системную функцию. Но делать это не рекомендуется. 
Особое внимание нужно уделить проверке входных параметров системной функции, так как syscall выполняется в пространстве ядра. Самой важной проверкой является проверка указателей(иначе может быть получен доступ к памяти, к которой программа не должна иметь доступа).

> В ядре предусмотрены две функции для выполнения необходимых проверок при копировании данных в пространство пользователя и из него: `copy_from_user()`, `copy_to_user()`.

Итак, `copy_from_user` необходима:
1. Они проверяют, находится ли предоставленный блок пользовательского пространства полностью в пользовательской части адресного пространства – это не позволяет приложениям  запрашивать ядро ​​для чтения/записи адресов ядра. Они возвращают ошибку, если какой-либо из адресов недоступен, позволяя вернуть ошибку в пространство пользователя (EFAULT) вместо сбоя ядра.
2. Ядро может случайно изменить данные пользователя в каком-то месте системной функции, поэтому лучше всегда иметь копию, а потом просто перекопировать в переданную структуру.
4. Платформозависимая реализация копирования.

Этапы добавления кастомного syscall:
1. Добавление в конец таблицы системных функций (файл entry.S). Новой системной функции будет назначен следующий свободный номер. Пусть это будет номер 338.
2. Добавление номера системной функции в `asm/unistd.h`: `#define __NR_foo 338`.
3. Добавить код функции в kernel/*.c, скомпилировать и добавить в ядро.

### Вызов своей системной функции


_syscalln загружает в регистры аргументы системной функции и генерирует exception.

```cpp
_syscalln()
```
где n — число от 0 до 6, соответствующее количеству параметров вызываемой системной функции.
