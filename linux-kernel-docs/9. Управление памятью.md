# 9. Управление памятью

Выделение памяти в ядре сложнее, чем выделение памяти для процессов. Здесь нельзя часто переходить в состояние ожидания.

## Страничная организация памяти

Основными единицами управления памятью в ядре являются страницы. 
MMU, Memory Management Unit — аппаратное устройство, которое отвечает за обращение к памяти и выполняет преобразование виртуальных адресов в физические, — обычно работает со страницами.

Обычно, для 32-х разрядных платформ размер страницы - 4Кб, для 64-x - 8Кб.

В Linux для каждой **физической страницы** выделяется структура `page`, которая ее описывает (все структуры занимают примерно 20МБ):
```c
struct page {
  unsigned long flags; 	// описывает состояние страницы
  atomic_t _count;  	  // количество ссылок на страницу в ядре. Если равен -1, то страница не используется, тогда она может быть перевыделена(заново выделять не нужно) другому процессу.
  void *virtual;       // виртуальный адрес страницы. Если физическая страница не может быть отображена в память (high memory), то NULL.
  ...
}
```

## Зоны памяти
Часть страниц из-за значений их физических адресов памяти нельзя использовать для решения некоторых типов задач. По этой причине в ядре вся физическая память разделена на зоны. Они используются в ядре для группировки физических страниц памяти, обладающих одинаковыми свойствами. Например:
1. Некоторые аппаратные устройства могут выполнять прямой доступ к памяти (DMA, Direct Memory Access) только в определенную область адресов.
2. На некоторых 32-разрядных аппаратных платформах адресуемый объем физической памяти может превышать адресуемый объем виртуальной памяти. Сле-
довательно, часть памяти не может постоянно отображаться в адресное пространство ядра.

Выделяются 4 зоны:
1. `ZONE_DMA` Содержит страницы памяти, к которым может обращаться контроллер DMA.
2. `ZONE_DMA32` Как и в ZONE_DMA, в этой зоне находятся страницы, доступные для контроллера DMA. В отличие от первой зоны обращаться к этим страницам
могут только 32-разрядные устройства. На некоторых аппаратных платформах эта зона занимает больший объем физической памяти.
3. `ZONE_NORMAL` Содержит страницы памяти, которые отображаются в адресные пространства обычным образом. Обычно содержит адреса, которые не попали в другие зоны.
4. `ZONE_HIGHMEM` Соответствует “верхней памяти” компьютера и состоит из страниц, которые не могут постоянно отображаться в адресное пространство ядра. Только на x86-32, на остальных процессорах пуста.

Разделение памяти на зоны и ее реальное использование зависят от аппаратной платформы, поэтому размер и адреса этих зон могут отличаться. 

Для обычных выделений памяти(если не указана зоны) могут использоваться DMA, NORMAL, хотя Linux старается всегда выделять из NORMAL.

Каждая из зон представляется в виде структуры `zone`.

## Выделение/освобождение страниц памяти в ядре

### Выделить размер, кратный страницы:
```c
struct page * alloc_pages(gfp_t gfp_mask, unsigned int order);
```

Данная функция позволяет выделить 2^order **смежных страницы (один непрерывный участок) физической памяти** и возвращает указатель на структуру page. В поле virtual структуры page содержится виртуальный адрес первой выделенной страницы.

Чтоб получить виртуальный адрес первой страницы:
```c
void * page_address(struct page *page);
```

```c
struct page * alloc_page(gfp_t gfp_mask) // выделение одной страницы физической памяти
```

Если нужно выделить 1 страницу, заполненную нулями, то можно воспользоваться:
```c
unsigned long get_zeroed_page(unsigned int gfp_mask);
```

Если нужно освободить страницу или несколько страниц:
```c
void free_pages(unsigned long addr, unsigned int order)
void free_page(unsigned long addr)
```

Важно освобождать только выделенные вам страницы, так как ядро полностью доверяет коду ядра.

## Выделение/освобождение количества байт

```c
void * kmalloc(size_t size, gfp_t flags); // выделить не менее size байт
```

Выделенный участок памяти физически находится на смежных страницах памяти.

Если нужно освободить данный участок памяти:
```c
void kfree(const void *ptr);
```

Функция `vmalloc()` выделяет **смежные страницы виртуальной памяти, которые необязательно являются смежными физически**. Точно так же работают и функции выделения памяти, используемые в пользовательских приложениях. Страницы памяти, выделяемые с помощью функции malloc(), являются смежными в виртуальном адресном пространстве процессора, но нет никакой гарантии, что они являются смежными в физической оперативной памяти.

```c
void * vmalloc(unsigned long size); // выделяет не менее size байт памяти
```

Освобождение:
```c
vfree(buf);
```

## Флаги gfp_mask

Флаги изменяют алгоритм работы системы выделения памяти.

`GFP_ATOMIC` - запрос высокоприоритетный, нельзя входить в ожидание при выделении памяти. Используется в обработчиках прерывания и в softirq
`GFP_KERNEL` - обычное выделение памяти в контексте  процесса, может входить в ожидание. 
`GFP_USER` - выделение памяти для пользовательского процесса
`GFP_DMA` - выделение памяти для операций DMA, может входить в ожидание

Некоторые флаги можно ORить.

## Уровень блочного распределения памяти
Выделение и освобождение памяти, занимаемой структурами данных, — одна из самых частых операций, которые выполняются в любом ядре. 
Блочный распределитель памяти является уровнем кеширования универсальных структур данных и служит для:
1. Часто используемые структуры данных, скорее всего, будут часто выделяться и освобождаться, поэтому их следует кешировать.
2. Уменьшение фрагментации памяти: частое выделение/освобождение фрагментируют память. Блочные кеши занимают непрерывные участки памяти, что уменьшает фрагментацию.
3. Блочный кеш уменьшает расходы на выделение и освобождение памяти.

### Реализация в Linux
Объекты, хранящиеся на блочном уровне, разделены на группы, называемые `кешами`(cache). Для каждого типа объектов существует свой уникальный кеш. 

Каждый кеш делится на `блоки`(slab), блок занимает одну или несколько смежных физических страниц памяти. Каждый кеш имеет несколько блоков.
В каждом блоке находится некоторое количество объектов. Каждый блок может быть в одном из трех состояний: `full` - нет свободных объектов, `partial` - есть и те и те, `empty` - все объекты свободны.

При каждом новом запросе ядро выделяет объект из partial блока, а если parial блока нет(блок может менять состояние), то выделяется из empty.

Пример кеша - `inode_cachep`, который состоит из структур inode, каждая из которых описывает индексы файлов с диска в оперативной памяти. 
Еще один пример - `task_struct_cachep`, который состоит из структур `task_struct`.
`mm_cachep` - содержит структуры `mm_struct`.

![image](https://imgbly.com/ib/DKOfy7v9nd.png)


Каждый кеш представлен в виде структуры `kmem_cache`. В ней есть три списка: slabs_full, slabs_partial и slabs_empty, каждый из которых описывает full, empty, parital блоки.
Каждый блок описывается структурой `slab`:
```c
struct slab {
  struct list_head list; /* Список заполненных, частично заполненных или пустых блоков */
  unsigned long colouroff; /* Смещение для окрашивания блока */
  void *s_mem; /* Указатель на первый объект блока */
  unsigned int inuse; /* Количество выделенных объектов */
  kmem_bufctl_t free; /* Первый свободный объект, если есть */
};
```
Создание нового кеша:

```c
struct kmem_cache * kmem_cache_create(const char *name,
    size_t size,
    size_t align,
    unsigned long flags,
    void (*ctor)(void *));
```

Удаление кеша:

```c
int kmem_cache_destroy(struct kmem_cache *cachep)
```

Получение объекта из кеша:

```c
void * kmem_cache_alloc(struct kmem_cache *cachep, gfp_t flags);
```

Чтобы освободить ненужный объект и вернуть его в блок, из которого он был выделен, используется следующая функция:

```c
void kmem_cache_free(struct kmem_cache *cachep, void *objp)
```

## Системный стек
	
До версий 2.6 системный стек ядра процесса был равен двум страницам памяти, После появилась возможность уменьшить стек до одной страницы.
Для пользовательских приложений стек может динамически расти. 
Для каждого обработчика прерываний выделяется свой стек(стек прерываний). Кроме того, он свой для каждого процессора. Занимает 1 страницу.

## Данные, выделяемые под конкретный процессор

Для этого есть интерфейс percpu.
	
На этапе компиляции можно определить переменную, каждая из которых будет связана со своим процессором:
```c
DEFINE_PER_CPU(type, name);
```

Получить переменную: 

```c
get_cpu_var(name)
```

Получить переменную другого процессора:

```c
per_cpu(name, cpu_num)
```

Если нужно выделить переменную на этапе выполнения кода ядра:

```c
alloc_percpu(type)
```
