### 1. Аудит на переполнение (Overflow Audit)

Move выполняет проверку переполнения при арифметических операциях, и транзакции с переполнением завершатся с ошибкой. Однако побитовые операции (bitwise) не проверяются на переполнение. [possibly fixed]

```move
    public fun bitwise_test(value: u8): u32 {
        (1 << value)
    }

    #[test]
    fun test() {
        let value = staking::bitwise_test(31); // not reverted
        let value = staking::bitwise_test(32); // reverted
    }
```

### 2. Аудит точности арифметики (Arithmetic Accuracy Deviation Audit)

Move не поддерживает числа с плавающей запятой.
```move
    public fun uint_test(a: u32, b: u32): u32 {
        a / b
    }

    #[test]
    fun test() {
        let value = staking::uint_test(100, 9); // 11, 100. / 9. = 11.(1)
        let value = staking::uint_test(100, 8); // 12, 100. / 8. = 12.5
    }
```

### 4. Access Control Audit
Проверять функции, которые работают с funds на предмет того, что только уполномоченные аккаунты могут их вызывать (owner of xCap). Может произойти ситуация, 
что для какой-то из функций доступ не ограничен - любой пользователь может вывести средства.

- аналог onlyOwner, onlyOperator...

### 5. Object ownership audit
В Sui объекты могут становиться shared, то есть публично доступными. Нельзя допускать, чтобы приватный объект был по ошибке переведён в shared.
Необходимо проанализировать все объекты: их тип, состояние (owned / shared) и права. Если найдено ошибочное превращение в shared — отметить как риск.

### 6. Аудит расходования токенов
Токены в Sui — это объекты. Их можно вкладывать в другие объекты, делать split и merge. Это гибко, но опасно: можно потерять контроль над токенами.

- правильно ли посчитана сумма расхода,
- корректно ли передан токен-объект,
- допустимы ли операции split/merge,
- как токен привязан к объекту.
