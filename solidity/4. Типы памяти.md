### Типы памяти

У всех типов памяти тип записи **little endian**.

- stack: direct
- storage: direct
- memory: reference
- calldata: reference, !mapping
- code: constant / immutable

Виды данных:
- direct (uintN, bytesN, bool, address, enums, internal/external funcs)
- miltivalue (type[N], struct)
- lookup (type[N], mapping, bytes, string)



- static (direct, multivalue)
- dynamic (!static)
- reference (multivalue / lookup)

В storage direct данные хранятся в packed виде, то есть упаковываются в слоты: например, 
есть есть два uint128, то они попадут в один слот, который 256 бит.

В memory / calldata / code - padded хранение, то есть каждый тип хранится

### stack

Стек используется при выполнении функций. 
На нем EVM выполняет вычисления. Напрямую обращаться к нему нельзя, 
к нему может быть обращаться только EVM. После завершения выполнения функции стек очищается

Может хранить только типы `direct`.

### code
Конструктор не попадает в code. Здесь хранится код контракта, кроме того здесь хранятся `const`, `immutable`.

### memory

#### Как выглядит?

EVM резервирует какую-то часто памяти(конечную) на машине.

Данную память можно использовать для временного хранения переменных во время вызова функции, после завершения функции данные не сохраняются.

memory гораздо дешевле, чем storage.

Состоит из слотов памяти, каждый слот - 32 байта (256 бит).

Все аргументы функции (неважно memory или calldata) передаются в ABI-кодированном виде. Если мы используем memory в аргументе функции, то перед выполнением тела функции в memory создасться 
раскодированная копия:
```
function transfer(address recipient, uint256 amount) external;
transfer(0xAbCdEf0123456789abcdef0123456789abcdef01, 1000);
1. function selector: bytes4(keccak256("transfer(address,uint256)")) = a9059cbb
2. address -> 000000000000000000000000AbCdEf0123456789abcdef0123456789abcdef01
3. uint256 -> 00000000000000000000000000000000000000000000000000000000000003e8

Total data: a9059cbb000000000000000000000000AbCdEf0123456789abcdef0123456789abcdef0100000000000000000000000000000000000000000000000000000000000003e8
```

Есть служебная память:
- 0x00 - 0x3f (2 слота): hashing methods  - служебное пространство для хэш методов
- 0x40 - 0x5f (1 слот): free memory pointers - указывает на следующее свободное место в memory
- 0x60 - 0x7f (1 слот): zero slots - используется для начального значения для динамического массива

Рассмотрим такой пример:
```solidity
contract MemoryLayout {
    // free slots:
    // - 0x80 - 0x9f
    // - 0xa0 - 0xbf
    // - 0xc0 - 0xdf
    
    function explore(string memory _str) external returns (uint ptr) {
        assembly {
            // str = "111"
            ptr := mload(0x40);    // вернется 192 (0xc0)
            data := mload(sub(ptr, 32)) // "0x3131310000...0000" // видимо в предыдущем слоте лежит размер строки
        }
    }
}
```

Еще один пример:
```solidity
contract MemoryExample {
    int[] public numbers
    
    function Numbers1() public {
        numbers.push(5)
        numbers.push(10)
        int[] memory myArray = numbers;

        myArray[0] = 1; // после выполнения функции в numbers будет 5, а не 1, так как в памяти создается копия numbers
    }
    
    function Numbers2() public {
        numbers.push(5)
        numbers.push(10)
        int[] storage myArray = numbers;

        myArray[0] = 1; // после выполнения функции в numbers будет 1, так как myArray указывает на ту же область памяти, что и numbers
    }
}
```


Могут храниться direct, reference, multivalue(), lookup (перед дин массивом идет длина, потом его данные).
Также сюда попадают постоянные переменные во время деплоя контракта, пока они не попали в байткод.
memory используется, чтобы хранить временные данные при выполнении функции.

### calldata

Используется для хранения аргументов функции у external функций.

Могут храниться типы direct, reference, !mapping.
Первые 4 байта - селектор функции, которая вызывается, далее идут аргументы. Доступна только для чтения.

```solidity
contract CalldataExample {
    // numbers = [1,2,3]
    function func(int[3] memory numbers) external returns (bytes) {
        // 0x1325ab1100000...
        // 100000000000000...
        // 200000000000000...
        // 300000000000000...
        return msg.data;
    }
}
```

Селектор получается следующим образом: 

```solidity
bytes4(keccak(bytes("func(int256[3])"))) // первые 4 байта от keccak256 от названия функции
```

### storage

Может хранить mapping, direct, reference, lookup.

Размечается во время деплоя контракта. Нельзя создать самому новый слот в storage в функции. 
Если происходит наследование, то переменные базового класса будут располагаться перед переменными дочернего.

#### Как хранятся byte arrays?

Если длина bytes < 32 байта, то [len][data], если >, то аналогично динамическому массиву.

#### Как хранятся динамические массивы? 

Длина массива занимает один слот, который называется главным слотом. 
Пусть номер данного слота p. Для того, чтоб получить слот, где лежат первые данные, вычисляется keccak256(p), 
потом этот хеш преобразуется к числу - номер слота начала хранения данных массива.

##### Как хранятся mapping?

У mapping тоже есть главный слот, который пустой. Конкатенируется (key # p) и считается keccak256 от этого значения.
И на этом слоте получаем value
