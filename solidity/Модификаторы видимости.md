### Модификаторы видимости

Модификаторы видимости обязательны, всего их бывает 4. Указывает на то, откуда функция может быть вызвана:

У функций есть следующие модификаторы:
- **external** - может быть вызвана из другого контракта (externalContractAddress.func()) или через транзакцию (может быть вызвана изнутри, но только this.func [нежелательно, так как много газа]). Если нужно вызвать
изнутри контракта, то можно назвать ее public. Кроме того, нельзя вызвать из другого контракта, который наследует родительский.
- **public** - может быть вызвана откуда угодно.
- **internal** - может быть вызвана изнутри и у контрактов, которые наследуют текущий
- **private** - может быть вызвана только изнутри и ниоткуда больше.

### View, pure

В solidity есть два типа функций - функции чтения(Read Contract) и функции записи(Write Contract). 
Функции чтения не вносят изменений в state variables, поэтому они бесплатные и вызвать их может кто угодно. 
Функции записи, напротив, могут изменять состояние какой-либо state variable, а потому они платные. 
`view` и `pure` применимы только к функциям чтения:

- **view** - помечаются функции, которые обращаются к переменным контрактам и возвращают либо эту переменную либо другую информацию, которая как-то связана с этой переменной
- **pure** - модификатором pure(чистый) помечаются функции, которые работают только с аргументами, которая эта функция принимает,
эти функции можно назвать изолированными от переменных контракта, потому что к ним функция никогда не обращается - собственно, поэтому эти функции чистые. Чистые функции, например, полезны для вычисления каких-то громоздких арифметических операций, которые удобно вынести в отдельный блок кода


### Constant, immutable

- **constant** - этим словом можно помечать переменные, которые никогда не будут изменены после компиляции контракта
- **immutable** - этим словом помечаются переменные значение которых назначается в момент деплоя контракта в конструкторе

### Virtual, override

- **virtual** - слово, говорящее о том, что эту функцию можно переопределить ниже по иерархии
- **override** - ключевое слово, ставится в контракте потомке, говорит о том, что функция уже переопределена
- **virtual override** - функция может иметь одновременно два слова, это говорит о том, что функция была переопределена в текущем контракте и может быть переопределена в контрактах ниже по иерархии наследования
