# 10. Адаптеры и представления

Адаптеры над стандартными контейнерами — это не самостоятельные контейнеры. Они используют какой-нибудь другой контейнер (например, дек или вектор) для хранения своих элементов, но при этом предоставляют свой набор функций для работы с ними. В стандартной библиотеке есть адаптеры `std::stack`, `std::queue` и `std::priority_queue`. 
Представления (`views`) не владеют памятью, а лишь ссылаются на диапазон значений другого контейнера. Представлением можно считать пару итераторов. В С++20 появилась обширная библиотека ranges для работы с представлениями.

> Теоретически, контейнером может выступать и кастомный класс, реализующий необходимые операции.
> Во всех адаптерах метод pop() не возвращает удаленный элемент, для этого используется top()

## std::stack (adapter)

Стек - структура данных LIFO. Произвольный доступ не допускается, возможно операции:\
`pop()` - удалить элемент с вершины стека\
`push()` - добавить элемент на вершину стека\
`top()` - получить элемент с вершины стека, сам элемент не удаляется.\

Также есть методы `emplace()` - перезапись вершины стека, `empty()`, `size()`.

По умолчанию стек использует контейнер `std::deque` для хранения элементов. При желании мы можем указать другой тип этого контейнера(`vector`, `list`, `deque`). Всё, что требуется от этого контейнера, — это поддержка операций `push_back`, `pop_back`, `back` и `empty`.

## std::queue (adapter)

Очередь - структура данных LIFO. Произвольный доступ не допускается, возможные операции:
`push() `- добавление в конец очереди
`pop()` - удаление из начала очереди
`front()` - получение элемента из начала очереди
`back()` - получение элемента из конца очереди

По умолчанию используется `std::deque`. Для того, чтобы использовать другой контейнер, необходимо, чтобы у него были реализованы методы `push_back`, `pop_front`, `back()`, `front()`. Поэтому `std::vector` не допускается, можно использовать только `std::deque`, `std::list`. 

## std::priority_queue (adapter)

Очередь с приоритетом(heap) позволяет получать максимальный элемент за O(1), добавлять и удалять элементы за  O(logn). Можно использовать контейнеры `std::vector`, `std::deque`, но нельзя `std::list` - нет произвольного доступа к элементам.

По умолчанию используется `std::vector`. 

Методы адаптера:
`push()` - добавление элемента
`pop()` - удаление элемента
`top()` - получение максимального элемента



## std::string_view (view)

Упрощенно представления можно представить в виде структуры:

```cpp
struct string_view { 
const char* start;  // указатель на начало подстроки в чужой памяти 
size_t len;   // длина этой подстроки 
};
```

В чем может быть проблема:
```cpp
std::string s = “Hello world”;
auto sub = s.substr(6,2); // “wo”
sub[0] = ‘W’;		// строка s не изменится, так как создалась копия.
```

При использовании substr создается копия. Если нужно просто получить подстроку исходной, которую нельзя менять, то можно использовать string_view. При этом копирования не произойдет. В string_view будет просто хранится указатель на память первой строки.

Обёртка string_view рассматривает исходную строчку как константную: она не позволяет её изменять. В то же время через string_view можно читать символы фрагмента исходной строки, а также можно брать новые подстроки и сужать длину подстроки:

```cpp
std::string s = "Hello, world! How do you do?"; 
std::string_view sv = s;  // смотрим через string_view на строку s 
auto sub = sv.substr(7, 5);  // теперь тип sub — std::string_view 
// sub[0] = 'W';  // изменять через string_view символы строки нельзя.
```

Важно следить, чтобы string_view указывал на валидную строку. Иначе UB.
