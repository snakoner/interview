# 1. Приведение типов

> Почему лучше не использовать C-style cast? Данный способ приведения не делает проверок на валидность приведения.

### const_cast

```cpp
const_cast<new_type>(exp);
```

Оператор приведения `const_cast` удаляет или добавляет квалификаторы `const` и `volatile` с исходного типа данных. Результирующий тип данных должен быть таким же, иначе не приведется.

```cpp
int a = 5;
int *p = &a;
// добавление константности
const int *pc = const_cast<const int *>(p);
*pc = 1 // compile error
```

### reinterpret_cast

Позволяет преобразовывать любой указатель в указатель любого другого типа. Также позволяет преобразовывать любой целочисленный тип в любой тип указателя и наоборот.

```cpp
int *ptr = new int[10];
char *ptrc = reinterpret_cast<char *>(ptr); // ok
```

Опасен, так как нет проверки совместимости.


### static_cast

Оператор приведения `static_cast` применяется для неполиморфного приведения типов на этапе компиляции программы. Отличие `static_cast` от приведения типов в стиле языка C состоит в том, что данный оператор приведения может отслеживать недопустимые преобразования, такие как приведение указателя к значению или наоборот (`unsigned int` к `double *` не приведет), а также приведение указателей и ссылок разных типов считается корректным только, если это приведение вверх или вниз по одной иерархии наследования классов, либо это указатель на `void`. В случае фиксации отклонения от данных ограничений будет выдана ошибка при компиляции программы.

### dynamic_cast

Оператор приведения `dynamic_cast` применяется для полиморфного приведения типов на этапе выполнения программы (класс считается полиморфным, если в нем есть хотя бы одна виртуальная функция). Если указатель, подлежащий приведению, ссылается на объект результирующего класса или объект класса производный от результирующего то приведение считается успешным. То же самое для ссылок. Если приведение невозможно, то на этапе выполнения программы будет возвращен NULL, если приводятся указатели. Если приведение производится над ссылками, то будет сгенерировано исключение `std::bad_cast`. Несмотря на то, что dynamic_cast предназначен для приведения полиморфных типов по иерархии наследования, он может быть использован и для обычных не полиморфных типов вверх по иерархии. В этом случае ошибка будет получена на этапе компиляции

## Типы данных

C++ - язык со статической типизацией. У каждой переменной на этапе компиляции должен быть чётко определённый тип данных. Про каждый тип данных заранее известно, сколько места в памяти занимает переменная такого типа.

Локальные переменные простых типов не инициализируются по умолчанию, Процессор просто выделит для них место на стеке процесса и их значение по умолчанию может быть любым.

Переменные составных типов(например `string`) инициализируются нулем (пустой строкой).

В случае глобальных переменных память будет проинициализирована 0, так как они помещаются в `bss` область.

Простые типы данных:
```cpp
char c = '1';    // символ 
bool b = true;   // логическая переменная, принимает значения false и true 
int i = 42;      // целое число (занимает, как правило, 4 байта) 
short int si = 17;           // короткое целое (занимает 2 байта) 
long li = 12321321312;       // длинное целое (как правило, 8 байт) 
long long lli = 12321321312; // длинное целое (как правило, 8 байт) 
float f = 2.71828;           // дробное число с плавающей запятой (4 байта) 
double d = 3.141592;         // дробное число двойной точности (8 байт)
long double ld = 1e15;       // длинное дробное (как правило, 16 байт) }
```

### В чем отличие long от long long?
В стандарте указано, что тип может занимать:
`long`: 32 бита и более
`long long`: 64 бита и более. 

Обычно long и long long занимают 64 бита.

Чтобы получить минимальное или максимальное значение типа:
```cpp
std::numeric_limits<int>::min()
std::numeric_limits<int>::max()
```

### Простые типы данных с фиксированных размером:

int8_t / uint8_t 
int16_t / uint16_t 
int32_t / uint32_t 
int64_t / uint64_t

### Переполнение
Беззнаковые типы можно спокойно переполнять: вычисления будут производиться по модулю соответствующей степени двойки.

### auto
Компилятор C++ умеет автоматически выводить тип переменной по значению, которое ей присваивается. Точный тип переменной всё равно становится известен в момент компиляции.

```cpp
auto a = 1; // int
auto b = 1.12 // double
auto c = 1UL; // unsigned long
auto s = “hello”; // char *
auto d; // не скомпилируется
```

Неявное преобразование типов:
```cpp
bool a = 1; // true
bool a = 0; // false
bool a = 1.1; // true
bool a = ‘c’; // true
```

Дробное значение отбрасывается:
```cpp
int a = 3.4;        // 3
int b = 3.6;        // 3
```

Если целое число содержит больше разрядов, чем может вместить мантисса, то разряды отбрасываются:
```cpp
float a = 35005;                // 35005
double b = 3500500000033;       // 3.5005e+012
```

Если переменной знакового типа (`signed`) присваивается значение не из его диапазона, то в этом случае результат не детерминирован. Программа может выдавать адекватный результат, а может работать некорректно.

### Преобразования в арифметических операциях:
Пусть складываются два числа:
a + b

Если диапазон a < диапазона b, то а преобразуется к типу b

Безопасное преобразование типов - такие преобразования, при которых не теряется точность:
```cpp
bool -> char -> short -> int -> double -> long double 
bool -> char -> short -> int -> long -> long long 
unsigned char -> unsigned short -> unsigned int -> unsigned long 
float -> double -> long double
```

Если речь идет об инициализации переменных, то, чтобы избежать опасных преобразований, когда может произойти потеря точности, рекомендуется использовать инициализацию в фигурных скобках:
```cpp
unsigned int a {-25};           // ! Ошибка компиляции
unsigned short b {-3500};       // ! Ошибка компиляции
```

Но вот это скомпилируется:
```cpp
unsigned int a = -25;           // 4294967271
unsigned short b = -3500;       // 62036 
```

При сложение `signed` и `unsigned`, `signed` приведется в `unsigned`.

> Tip
Пусть нам надо сравнить два числа с плавающей запятой. Лучше напрямую их не сравнивать:
```cpp
int main() {
	double x = 0.1, y = 0.2; 
	if (x + y == 0.3) {
		std::cout << "EQUAL ";
	} else { 
		std::cout << "NOT EQUAL "; 
	} 

	std::cout << x + y << "\n";
}
```

Лучше сделать так:
```cpp
double delta = 0.000001; 
double x = 0.1, y = 0.2; 
double sum = x + y; 
if (std::abs(sum - 0.3) < delta) { 
	std::cout << "EQUAL "; 
} else { 
	std::cout << "NOT EQUAL "; 
}

std::cout << sum << "\n";
```

Так как их разница может быть отлична от 0 в битовом представлении.
