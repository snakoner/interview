# 11. Классы 

## Отличия классов от структур:

1. По умолчанию поля в классе private, поля структур public.
2. Экземпляр класса называется объектом, экземпляр структуры называется структурная переменная.
3. Классы принято использовать, чтобы создать абстракцию данных, описать логику и для дальнейшего наследования, структура просто объединяют данные.
4. Отличается и наследование по умолчанию, у struct — public, у class — private.

Доступ к `private` полям класса возможен только из дружественных функций и функций класса.

Объявлять функции класса обязательно в классе. Определять их можно и вне класса с использованием `ClassName::FuncName()`.

Если метод класса объявлен как `const`, то он не может менять состояние объекта данного класса:

```cpp
class Test {
private:
	int x;
public:
	int getX() const {
		x++; // compile error
		return x;
  	}
};
```

Объект в теле функции класса доступен через указатель `this`, он передается неявно.

Если входные параметры конструктора невалидны, есть два случая разрешения этого:
1. Кинуть исключение: например throw std::out_of_range().
2. Задать параметры по умолчанию.

Плохо просто делать return, так как в полях был бы мусор.

## Перегрузка конструктора

Конструкторы можно перегружать:

```cpp
class Time {
private:
	int minutes;
public:
	Time(int m) : minutes(m) {} 
}

int main() {
	Time t; // compile error
}
```

```cpp
class Time {
private:
	int minutes;
public:
	Time() : Time(0) {} 
	Time(int m) : minutes(m) {} 
}

int main() {
	Time t; // OK
}
```

Можно также указать дефолтные значения для полей класса:

```cpp
class Time {
private:
	int minutes = 0;
public:
	Time() = default;
	Time(int m) : minutes(m) {} 
}

int main() {
	Time t; // compile error
}
```

В этом случае(default), компилятор создаст конструктор с пустым телом, и проинициализирует начальными значениями, если они есть. Если нет, то мусор.


## Константность

У константных объектов можно вызвать только методы, помеченные как const.

```cpp
class Time {
  ...
public:
	void AddSeconds(int sec) {
		seconds += sec;
  	} 
}

const Time t;
t.AddSeconds(1); // compile error

Time tt;
const Time& cref = tt;
cref.AddSeconds(1); // compile error
```

## Перегрузка операторов

```cpp
Time& operator+=(int min) {
	minutes += min;
	return *this;
}
```

Возвращаем ссылку на тот же самый объект.
Если предполагается создавать новый объект, то нельзя возвращать ссылку или указатель, так как он создастся в области видимости функции, при выходе из нее он будет удален и нет гарантии достоверности данных в этой памяти.

```cpp
public:
Time operator+(int min) const {
	return Time(minutes + min);
}
```

Но лучше определять перегрузку операторов во внешней области:

```cpp
Time operator+(const Time &t, int min) {
	return Time(t.getMinutes() + min)
}
```

Здесь уже нельзя указать const.

## Перегрузка операторов ввода-вывода

```cpp
std::ostream& operator<<(std::ostream& os, const Time& t) {
	os << t.getMinutes();
	return os;
}
```

Зачем возвращать ссылку на поток? Чтоб можно было сделать цепочки вида:
```cpp
std::cout << t1 << “ ”  <<  t2; 
```


```cpp
std::istream& operator<<(std::istream& is, Time& t) {
	int mins;
	is >> mins;
	t.setMins(mins);

	return is;
}
```
