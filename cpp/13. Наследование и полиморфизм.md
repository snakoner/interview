# 13 Наследование и полиморфизм

![image](https://github.com/snakoner/interview/assets/26333766/c5ba4f8c-84c2-4946-8f8c-e60daebdbacd)

## Уровни доступа:
`private` - переменные и функции могут быть использованы внутри базового класса, не видны вне базового класса(при наследовании или использовании в коде программы).\
`protected` - переменные и функции видны в классе-наследнике, но не видны вне класса и класса-наследника.\
`public` - переменные и функции видны в классе-наследнике и вне класса.

## Виды наследования:
`public` - public и protected наследуются без изменения доступа к ним.\
`protected` - все унаследованные переменные и функции становятся защищенными(protected -> protected, public->protected, private->private).\
`private` - все унаследованные переменные и функции становятся приватными. Т.е protected и public видны в классе наследнике( становятся в этом классе приватными), но не видны вне.


**Наследование** — это способ организовывать иерархии классов. При этом класс-наследник приобретает поля и функции базового класса, модифицируя их область видимости.

```cpp
class A { 
private: 
  int x; 
public: 
  void Func1(); 
  void Func2(); 
};

class B: public A { 
private: 
  int y; 
public: 
  void Func2(); 
  void Func3(); 
};
```

Технически класс B включает в себя подобъект класса A. Класс B приобретает поля и функции базового класса A, возможно, меняя их уровень доступа.

```cpp
int main() { 
  B b; 
  b.Func1();  // унаследована от A 
  b.Func2();  // переопределена в классе B 
  b.A::Func2();  // версия Func2 из класса A 
  b.Func3();  // определена в классе B 
}
```

Приватное поле x в функциях класса B оказывается недоступным (как и в любом другом месте кода), однако оно хранится внутри объекта типа B и может быть изменено функциями из A.

Самое заманчивое, что тип B может быть приведён к типу A. Поэтому объект класса B может использоваться везде, где ожидается A:

```cpp
void DoSomething(const A&); 

int main() { 
  B b; 
  DoSomething(b);  // ok 
}
```

Так происходит вызов конструкторов/деструкторов у класса-наследника:

```cpp
constrctor_A(); // implicit
constrctor_B();
~destructor_B();
~destructor_A();
```

> Важно: класс потомок может быть автоматически приведен к типу класса-родителя.

## Наследование и композиция

**Композиция** — использование класса в качестве типа поля другого класса.

Публичное наследование автоматически приносит в интерфейс класса-наследника функции из базового класса и позволяет наследнику притворяться объектом базового типа. Напротив, композиция приносит объект исходного класса как именованное поле, а для предоставления доступа к его функциям требуется писать обёртки.

## Полиморфизм

Важная особенность наследования — возможность заменять поведение функций базового класса в классах-наследниках. Она называется полиморфизмом.

Пусть есть:

```cpp
class Animal {
private:
   std::string name;
public:
   Animal(const std::string& a) : name(a){}
   void voice() const {
       std::cout << "General voice" << std::endl;
   }
};


class Dog : public Animal {
public:
   Dog(const std::string& a) : Animal(a){}
   void voice() const {
       std::cout << "Dog voice" << std::endl;
   }
};




class Cat : public Animal {
public:
   Cat(const std::string& a) : Animal(a){}
   void voice() const {
       std::cout << "Cat voice" << std::endl;
   }
};


void makeVoice(const Animal& a) {
   a.voice();
}


int main(int argc, const char *argv[]) {
   makeVoice(Dog("dog"));
}
```

В данном случае выведется `General voice`, а не `Dog voice`, так как функция makeVoice ничего не знает про наследников класса `Animal`.

Решить это можно с помощью виртуальных функций.

## Виртуальные функции

В предыдущем примере происходило ранее связывание. Еще на этапе компиляции компилятор подставлял на место a.voice функцию Animal::voice.

Виртуальные функции позволяют делать позднее связывание. В таком случае выбор функции происходит в runtime.

Для этого в базовом классе функцию нужно объявить виртуальной:

```cpp
{
	virtual void voice() {
	std::cout << “General voice” << std::endl;
}
}
```

А в наследниках, в которых мы хотим переопределить функцию,  можно написать override(но не обязательно):

```cpp
{
	void voice() override {
    ...
  }
}
```

### Как работают виртуальные функции:

Если в базовом классе объявлена хотя бы одна виртуальная функция, то компилятор добавляет к классу ещё одно неявное поле — указатель на таблицу виртуальных функций. Конструкторы базового класса и классов-наследников меняют этот указатель, чтобы он указывал на таблицу виртуальных функций именно этого класса. Для выбора нужной функции надо сначала перейти по этому указателю на таблицу, а потом уже вызвать функцию. Это медленнее, чем обычный вызов функции. Виртуальные функции имеют свои накладные расходы, и поэтому функции класса не являются виртуальными по умолчанию.

### Чисто виртуальные функции

Заметим, что мы нигде явно не создаём объекты базового класса Animal. Поэтому функцию Animal::Voice можно объявить чисто виртуальной вот так: 

```cpp
class Animal { 
public: 
  virtual std::string Voice() const = 0;  // чисто виртуальная функция 
}; 
```

У чисто виртуальной функции даже не обязательно должна быть реализация. Если в классе есть такая функция, то класс считается абстрактным. Создать объект такого класса (например, написать Animal a) не получится, так как класс считается не полностью определенным. Назначение чисто виртуальных функций — потребовать, чтобы классы-наследники переопределили это поведение, иначе они тоже будут считаться абстрактными и их нельзя будет создать.

## Полиморфизм и контейнеры

Пусть есть вектор Animal:

```cpp
std::vector<Animal> zoo;
   zoo.push_back(Cat("Tom"));
   zoo.push_back(Dog("Buffa"));
   // Тут можно было бы написать цикл,
   // но мы напишем два вызова для наглядности
   Process(zoo[0]);  // Tom: Generic creature voice!
   Process(zoo[1]);  // Buffa: Generic creature voice!
}
```

Вызываются функции от Animal, так как в векторе хранятся копии переданных в push_back объектов, и эти копии имеют тип Animal.

Можно положить в вектор указатели Animal *. Но если выделять их на стеке - плохо, указатели могут перетереться: Эти объекты разрушаются при выходе из блока. Поэтому будет плохо возвращать такой вектор из функции — все указатели в нём станут сразу невалидными.
```cpp
std::vector<Animal*> zoo;
// Создадим пока что объекты на стеке
Cat c("Tom");
Dog d("Buffa");
// Кладём в вектор адреса этих объектов
zoo.push_back(&c);
zoo.push_back(&d);
// Для разыменования нужна звёздочка
Process(*zoo[0]);  // Tom: Meow!
Process(*zoo[1]);  // Buffa: Woof!
```

Можно создать динамические объекты в куче:

```cpp
std::vector<Animal*> zoo;
zoo.push_back(new Cat("Tom"));
zoo.push_back(new Dog("Buffa"));
Process(*zoo[0]);  // Tom: Meow!
Process(*zoo[1]);  // Buffa: Woof!
```

Мы создали объекты в динамической памяти, но не освободили эту память в конце. Это грубая ошибка. Мы должны были вызвать delete, когда эта память станет ненужной. Ещё важно, чтобы для животных вызывался правильный деструктор — ~Cat для кошки, ~Dog для собаки. Поэтому, если в базовом классе есть виртуальные функции, и с ним предполагается полиморфная работа с созданием объектов в динамической памяти, то деструктор базового класса необходимо объявить виртуальным:

```cpp
class Animal {
public:
   // ...
   virtual ~Animal() {
   }
};
```

Заметим, что такая работа с динамическими объектами очень опасна. Мы можем по какой-то причине не дойти до цикла с уничтожением объектов. Более правильным было бы использовать вектор умных указателей std::vector<std::unique_ptr<Animal>>. Тогда писать цикл с вызовами delete было бы не нужно.
