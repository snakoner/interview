
## Этапы
1. BIOS/UEFI (содержится в ПЗУ на материнской плате) -> MBR
2. MBR -> GRUB2
3. GRUB2 -> Kernel
4. Kernel -> init/systemd
5. init/systemd

## BIOS[Basic I/O system] (в современных версиях UEFI)
1. После включения питания CPU читает код BIOS в RAM и выполняет его.
2. Код производит POST (power-on-self-test) тестирование: проверка валидности кода BIOS(используя check sum), проверка аппаратных модулей(DMA, RAM, system timer), настройка некоторых их параметров, такие как частота. Если тут есть проблемы, загрузка системы дальше не идет.

## MBR
1. Если POST тест прошел успешно, то код BIOS выполняет поиск MBR(master boot record) - код и данные, которые располагаются в первом секторе жесткого диска и занимает 512 байт. MBR указывает, в каком месте на жестком диске расположен вторичный загрузчик(GRUB, GRUB2).
2. Код GRUB2 загружается в RAM и управление передается ему.

## GRUB2
1. Функция GRUB2 состоит в том, чтобы найти и загрузить ядро ​​Linux в оперативную память и передать управление компьютером ядру. Ядро и связанные с ним файлы находятся в каталоге /boot. Само ядро хранится в сжатом формате в файле vmlinuz-*.
2. GRUB2 может найти не одно ядро ОС, а несколько и предложить на выбор, какому из них передавать управление.

## Kernel
1. vmlinuz саморазархивируется.
2. Так как файловая система еще не смонтирована, то ядро использует временную файловую систему из файла initrd.img.
3. Ядро запускает init или systemd.

## init/systemd
1. init смотрит файл /etc/inittab, чтоб определить уровень выполнения(runlevel): однопользовательский режим, многопользовательский режим, ...
2. systemd монтирует файловую систему из /etc/fstab.
