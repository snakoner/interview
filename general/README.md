**1. Сигналы**

Когда сигнал послан процессу, ядро Linux прерывает выполнение процесса (важно, что в этот момент процесс выполнятеся, то есть глобальные переменные в обработчике доступны). При этом, если процесс установил собственный обработчик сигнала, операционная система запускает этот обработчик, передав ему информацию о сигнале, если процесс не установил обработчик, то выполняется обработчик по умолчанию.

Сигналы могут посылаться:
1. из управляющего терминала:
- Ctrl+Z - **SIGTSTP** (terminal stop): приостановка выполнения сигнала, чтобы продолжить выполнение процесса нужно отправить **SIGCONT**
- Ctrl+/ - **SIGQUIT** - завершение с дампом памяти.
- Ctrl+C - **SIGINT** - по умолчанию завершает процесс, если не перегружен обработчик
2. Ядром Linux:
-  возникновении аппаратных исключений (недопустимых инструкций, нарушениях при обращении в память, системных сбоях)
-  ошибка при системном вызове
-  для информирования о событиях ввода-вывода
3. Одним процессом другому (или самому себе), с помощью системного вызова kill(), или из bash/kill


Обработчик по умолчанию для большинства сигналов завершает выполнение процесса. Нельзя перегрузить SIGKILL(немедленное завершение), SIGSTOP(приостановка).
Сигналы не могут быть посланы зомби-процессу.

**2. Сокеты**

**Cокет** — это конечная точка двустороннего канала связи, установленного между двумя процессами.

Сокеты могут использоваться для организации взаимодействия процессов:
1.  На одном компьютере
2.  По локальной сети
3.  Через Internet
4.  Кроме того, с их помощью можно организовать взаимодействие с программами, работающими под управлением других операционных систем. Например, под Windows существует интерфейс Window Sockets, спроектированный на основе **socket API**.

В процессе сокет идентифицируется с помощью дескриптора (int).

Создание сокета:
```cpp
int socket(int domain, int type, int protocol);
// domain - AF_UNIX - взаимодействие на одной машине, AF_INET - взаимодействие по сети internet
// type - SOCK_STREAM(TCP), SOCK_DGRAM(UDP), SOCK_RAW(Ethernet, ICMP)
```

Назначение адреса сокету:
```cpp
int bind(int sockfd, struct sockaddr *addr, int addrlen);
```

Сервер:
```
listen(); // прослушивание сокета
accept(); // блокировка процесса сервера, пока клиент не подключится к сокету
```

Клиент:
```cpp
connect(); // подключение к сокету
```

Клиент/сервер:
```cpp
send()
recv()
```

**3. Симуляторы и эмуляторы**


Эмуляторы - сосредоточены на воссоздании поведения системы, не обращая внимания на то, как система функционирует внутри.
Симуляторы - фокусируется на моделировании компонентов системы.

Вы используете эмулятор, когда вас больше всего волнует то, что делает система, и симулятор, когда вас интересует, как она это делает.
