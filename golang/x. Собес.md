1. Что такое Go и в чем его основные преимущества?
	Go — это компилируемый язык программирования, разработанный Google. Его основные преимущества:
	- Простота и лаконичность синтаксиса
	- Высокая производительность (сравнима с C++)
	- Встроенная поддержка конкурентности (goroutines, channels)
	- Автоматический garbage collector
	- Кроссплатформенность: Go особенно удобен в этом плане, так как позволяет компилировать один и тот же код для разных ОС без необходимости менять его: `GOOS=linux` `GOARCH=amd64` go build

2. Чем отличается var от :=?
	- var используется для явного объявления переменной с указанием типа
	- := — короткое объявление переменной без явного указания типа, доступно для объявления только внутри функции

6. Как устроены строки в Go?

	В Go строка в является слайсом байт, доступным только для чтения. Строка содержит произвольные байты, и у неё нет ёмкости (cap).
	При преобразовании слайса байт в строку (str := string(slice)) или обратно (slice := []byte(str)) — происходит копирование массива.
	
	Go использует тип rune (алиас int32) для представления Unicode. Конструкция for ... range итерирует строку посимвольно (а не побайтово, как можно было бы предположить):
	
	```go
	var str = "привет"
	
	for i, c := range str {
	    fmt.Println(i, c, string(c))
	}
	
	// 0 1087 п
	// 2 1088 р
	// 4 1080 и
	// 6 1074 в
	// 8 1077 е
	// 10 1090 т

	fmt.Println(len(str)) // 12
	
	for i := 0; i < len(str); i++ {
	  fmt.Println(str[i]) // побайтово
	}
	```

 	Эффективным способом работы со строками (когда есть необходимость часто выполнять конкатенацию, например) является использование слайса байт или strings.Builder, который всегда использует один и тот же буфер.

7. Как увеличивается размер slice?

   	Добавление элемента в slice происходит при вызове slice = append(slice, value). Если len < cap, то append вернет копию с тем же ptr. Если len == cap, то выделится новая область памяти и append вернет копию slice, но уже с новым ptr.
   
	Увеличении размера слайса (метод growslice) происходит по следующему алгоритму — если его размер менее 1024 элементов, то его размер будет увеличиваться вдвое; иначе же слайс увеличивается на ~12.5% от своего текущего размера.

8. Какое у слайса zero value? Какие операции над ним возможны?

	nil

	```go
	 var a []int
	
	println(a == nil, len(a), cap(a)) // true 0 0
	a = append(a, 1)
	println(a == nil, len(a), cap(a)) // false 1 1
 	```

10. Что такое unsafe.Pointer?

	В Go unsafe.Pointer — это универсальный указатель, который позволяет обходить систему типов и манипулировать памятью напрямую. Он находится в пакете unsafe и используется в крайних случаях, когда нужна низкоуровневая работа с указателями.

11. Что такое контекст в Go?

	В Go пакет context используется для управления **тайм-аутами(timeout, deadline)**, **отменой операций(gracefull shutdown)** и **передачи значений между функциями**. Это особенно полезно в конкурентных программах, работающих с goroutine.

	Виды:

	1. context.Background() - Базовый (нулевой) контекст, который используется как родительский для других контекстов
	2. context.TODO() - Используется, если непонятно, какой контекст использовать (например, при разработке или рефакторинге кода).
	3. context.WithCancel(parent) - Создаёт контекст с возможностью отмены
	
		```go
		ctx, cancel := context.WithCancel(context.Background())
		
		go func() {
			time.Sleep(2 * time.Second)
			cancel() // Отменяем контекст через 2 секунды
		}()
		
		<-ctx.Done() // Блокируем выполнение, пока контекст не будет отменён
		fmt.Println("Контекст отменён:", ctx.Err()) // context canceled
		```
	4. context.WithTimeout(parent, duration) - Создаёт контекст, который автоматически отменяется через заданное время.
		
		```go
		ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
		defer cancel() // Всегда освобождаем ресурсы
		
		select {
		case <-time.After(5 * time.Second):
		    fmt.Println("Операция завершена")
		case <-ctx.Done():
		    fmt.Println("Тайм-аут:", ctx.Err()) // context deadline exceeded
		}
		```
	5. context.WithDeadline(parent, time) - Аналогично WithTimeout(), но указывает конкретный момент времени, когда контекст истечёт.
	6. context.WithValue(parent, key, value) - Позволяет передавать данные через контекст.
		
		```go
		ctx := context.WithValue(context.Background(), "userID", 42)
		
		func process(ctx context.Context) {
		    userID := ctx.Value("userID").(int)
		    fmt.Println("User ID:", userID)
		}
		
		process(ctx)
		```
12. Как ООП в Go?
    - Наследования нет - есть встраивание структур в структуры и интерфейсов в интерфейсы.
    - Инкапсуляция - изоляция полей структур - видны только в пакете, при импорте из других пакетов поля структуры не видны.
    - Полиморфизм - интерфейсы, generics.

13. Отличие slice от array:
    - array - имеет фиксированную длину, длина должна быть известна на момент компиляции, представляет из себя указатель на область непрерывной памяти.
    - slice - (ptr, len, cap), надстройка на array, может менять длину.
    ```go
	a := [5]int{1, 2, 3, 4, 5} // array
	slice := a[:] // slice, ptr to array

	fmt.Printf("%p\n", &a)	// 0x14000128000
	fmt.Printf("%p\n", &slice[0]) //0x14000128000

    ```
    
	```go
	a := 3
	arr := [a]int{1, 2, 3} // compile error

	const aa = 3
	arr := [aa]int{1, 2, 3} // ok
	```

	- При append до 1024 увеличение cap в 2 раза в случае, если len == cap, после на 12.5%.

32. Зачем создавать дочерний контекст от родительского контекста?
> - Отмена родительского контекста автоматически вызывает отмену всех дочерних контекстов. Это важно для пропагирования отмены операций между различными частями программы.
> - Дедлайн и таймауты в дочернем контексте можно настроить независимо, что дает гибкость для различных операций.

35. В Go переменные в **замыканиях захватываются по ссылке** (by reference), а не по значению. Это значит, что замыкание запоминает саму переменную, а не её текущее значение на момент создания замыкания.

36. Что означает запись slice[1:3:3]

```go
	s := []int{1, 2, 3, 4, 5, 6}
	fmt.Println(s[1:3:5]) // [2, 3]
	fmt.Println(len(s[1:3:5])) // 2
	fmt.Println(len(s[1:3:5])) // 5

	// последний параметр означает cap нового среза
```

### Non Golang

**1. SQL | NOSQL**

- **Структура данных**: SQL - Таблицы (строки и столбцы), NoSQL - Ключ-значение, документы, графы, колонки

- **Язык запросов**: SQL: SQL, NoSQL: MongoDB – BSON, Redis – команды.

- **Схема**: SQL: Жесткая, заранее определенная, NoSQL - гибкая

- **Масштабируемость**: Вертикальная (мощный сервер) | Горизонтальная (много серверов)

- **Целостность данных**: Высокая | Гибкая, высокая скорость (BASE)

- **Производительность**: Оптимизирована для сложных запросов | Быстрее при больших объемах данных и изменениях

- **Применение**: Финансы, бухгалтерия, CRM, ERP | Big Data, IoT, соцсети, кеширование

Когда использовать SQL?

	- Данные структурированные (таблицы, строгие правила).
	- Важна целостность (банковские операции, финансы).
	- Используются сложные запросы (много JOIN, агрегаций).

Когда использовать NoSQL?

 	- Гибкая структура данных (изменяющаяся схема).
	- Высокая нагрузка и горизонтальное масштабирование (социальные сети, стриминг).
	- Документ-ориентированное хранилище (JSON/ BSON).

Примеры NoSQL: 

 	- Redis: ключ-значение
	- MongoDB: JSON-подобные документы

	Что такое целостность данных: Атомарность, согласованность, изолированность, долговечность. Гарантирует, что транзакции выполняются полностью или не выполняются вообще.

**3. Что такое Prometheus?**

Prometheus – это система мониторинга и алертинга

Что мониторит Prometheus?
- CPU, RAM, диск, сеть (нагрузка серверов)
- Запросы в API, время отклика
- Ошибки, статус сервисов
- Метрики Kubernetes (K8s)
- Базы данных (PostgreSQL, MySQL)

**4. Виды тестирования на примере Go?**

1. Юнит-тесты: Тестирование отдельных функций или модулей: **testing, testify**
2. Интеграционные тесты: Проверка взаимодействия нескольких модулей(например, API + база данных)
3. Функциональные тесты: Проверка работы приложения с точки зрения пользователя. Обычно эмулируются API-запросы и пользовательские сценарии.
4. Нагрузочные тесты: **k6**

4. Как спроектировать масштабируемую систему?

- Горизонтальное(больше серверов) vs. вертикальное масштабирование(увеличение мощности сервера: cpu, ram, ssd).
- Разделение нагрузки (Load Balancing).
- Кеширование (Redis, Memcached).
- База данных (SQL vs. NoSQL, репликация, шардинг).
- Асинхронная обработка (Kafka, RabbitMQ).

5. CAP-теорема (Consistency, Availability, Partition Tolerance) описывает ограничения распределённых систем. Она гласит, что в любой распределённой системе из трёх свойств можно гарантировать только два одновременно.
   - Consistency (Согласованность):
   	- Все узлы видят одно и то же актуальное состояние данных.
   	- После записи, все последующие чтения вернут последнее записанное значение.
   - Availability (Доступность):
   	- Каждый запрос получает ответ (даже если данные могут быть устаревшими).
   	- Система работает всегда, но может отдавать не самые свежие данные.
   - Partition Tolerance (Устойчивость к разделению сети):
   	- Система продолжает работать, даже если узлы не могут связаться друг с другом.
