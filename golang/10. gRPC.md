gRPC (Google Remote Procedure Call) — это высокопроизводительный RPC-фреймворк от Google, который использует protobuf для сериализации данных и работает поверх HTTP/2. Он позволяет сервисам вызывать функции на удалённых серверах, как если бы это были локальные методы.

### Основные особенности gRPC
1. Работает поверх HTTP/2
2. Поддерживает мультиплексирование (несколько запросов в одном соединении)
3. Строгая типизация
4. Генерация кода для разных языков (Go, Python, Java, C++, Rust и т. д.)
5. Более компактный и быстрый по сравнению с JSON или XML

### Поддержка 4 типов взаимодействий
1. Unary (Обычный запрос-ответ): 1 запрос -> 1 ответ
2. Server Streaming: 1 запрос -> поток ответов
3. Client Streaming: поток запросов -> 1 ответ
4. Bidirectional Streaming: поток запросов <-> поток ответов

### Как использовать
Генерация кода из .proto файлов позволяет легко создать клиент и сервер на разных языках

gRPC требует файл .proto, который описывает структуру API:

```proto
syntax = "proto3";

package myservice;

service Greeter {
  rpc SayHello (HelloRequest) returns (HelloReply);
}

message HelloRequest {
  string name = 1;
}

message HelloReply {
  string message = 1;
}
```

Генерация gRPC-кода:

```bash
protoc --go_out=. --go-grpc_out=. myservice.proto
```


### protobuf

Поддерживает следующие типы:

1. Скалярные (примитивные) типы:
   - double, float
   - int32/64, uint32/64, sint32/64 (эффективное кодирование, хорошо для отрицательных чисел)
   - bool
   - string (utf8)
   - bytes (бинарные данные, например файлы, изображения)

2. Массивы:

```proto
message Person {
  repeated string hobbies = 1;  // Список хобби
  repeated int32 scores = 2;    // Список оценок
}
```

3. Map:
- Ключ (key) должен быть скалярным типом (int32, string и т. д.)
- Ключи bytes, float, double не поддерживаются!

```proto
message PhoneBook {
  map<string, string> contacts = 1;
}
```

4. Вложенные структуры

```proto
message Address {
  string street = 1;
  string city = 2;
}

message Person {
  string name = 1;
  Address address = 2;  // Вложенный объект
}
```

5. Enum (перечисления):

```proto
enum Status {
  UNKNOWN = 0;
  ACTIVE = 1;
  INACTIVE = 2;
}

message User {
  string name = 1;
  Status status = 2;
}
```

6. Опциональные поля (optional)

```proto
message Person {
  optional string nickname = 1;  // Может отсутствовать
}
```

7. Any (гибкий тип для разных структур)

Используется для динамических данных (например, вложение разных типов в одно поле):

```proto
message Data {
  google.protobuf.Any payload = 1;
}
```
