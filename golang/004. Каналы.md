Инструмент коммуникации между горутинами, представляет из себя структуру. Каналы живут на heap

Типы:  
1. Буферизированные (есть слоты для элементов, до блокировки горутин)  
2. Небуферизированные (нет слотов, обмен между горутинами происходит напрямую через sendDirect() в их стэк)

  
##### Nil канал - любая операция блокирует горутину навсегда. 
##### Закрытый канал: 
- Чтение -> возвращает zero-value + `ok = false` 
- Запись -> panic 

#### Структура
Основные сущности: 

 
```go
type hchan struct { 
  qcount uint // количество элементов в буфере (кол-во элементов в канале на данный момент) 
  dataqsiz uint // размерность буфера (сколько слотов у него есть всего) 
  buf unsafe.Pointer // ссылка на буфер данных (кольцевая очередь) 
  elemsize uint16 // размерность одного элемента в канале (байт) 
  closed uint32 // флаг закрыт или открыт канал в данный момент (не bool, потому что используется atomic) 
  elemtype *_type // ссылка на тип данных в канале 
  sendx uint // индекс смещения записи (в какой индекс буфера будет след запись) 
  recvx uint // индекс смещения чтения (из какого индекса буфера будет след чтение) 
  recvq waitq // очередь заблокир горутин (sudog), ожидающих чтение. (связ список)  // кто хочет прочитать, но не может
  sendq waitq // очередь заблокир горутин (sudo), ожидающих записи (связ список) // кто хочет записать, но не может
  Lock mutex // мьютекс для блокировки буфера 
} 
```

```
type waitq struct { 
  first *sudog - голова списка 
  last *sudog - хвост списка 
} 
```

```
type sudog struct { 
  g *g - ссылка на горутину 
  elem unsafe.Pointer - данные для записи (в ресивере это ссылка на то где они должны лежать) 
}
```

#### Алгоритм работы

gopark — это внутренняя функция runtime Go, которая паркует (усыпляет) текущую горутину и отдаёт управление планировщику.

#### Send (ch <- v): 
- Если есть ожидающий получатель → sendDirect() → пробуждение получателя (goready). 
- Если буфер есть и свободен → запись в buf[sendx]. 
- Иначе → gopark() → вставка в sendq (waiting). 

#### Receive (v := <-ch): 

- Если есть ожидающий отправитель → sendDirect() → пробуждение отправителя. 
- Если буфер не пуст → чтение buf[recvx] + сдвиг индекса, возможно пробуждение из sendq. 
- Иначе → gopark() → вставка в recvq (waiting). 

#### Close (close(ch)): 

Ставит closed=1. 

- Будит всех из recvq → они получают zero-value. 
- Будит всех из sendq → у них panic. 

- Любая попытка send после close -> паника. 
- Receive после close -> zero-value + `ok = false` 


| Состояние канала      | Чтение                               | Запись                               | Закрытие            |
|-----------------------|---------------------------------------|---------------------------------------|---------------------|
| Открытый              | блокировка до прихода значения        | блокировка до прихода читателя (для unbuffered) | канал закроется |
| Закрытый              | вернётся zero value (`ok = false`)    | panic                                 | panic               |
| Неинициализированный (`nil`) | блокировка навсегда                 | блокировка навсегда                   | panic               |

```
Select: 
- Механизм одновременного ожидания нескольких операций на каналах. 
- Если несколько веток готовы → выбирается случайно (fairness). 
- Если ни одна не готова и нет default → горутина блокируется. 
- Примерно как «расширенный Receive/Send» с возможностью таймаутов и default.
```
