### Каналы в go

`Канал` - объект, с помощью которого горутины могут обмениваться данными. Из канала можно читать и писать (по умолчанию). Каналы бывают буфферизированными и небуфферизированными.
Каналы являются потокобезопасными (можно работать с ними без использования блокировок, так как блокировки есть внутри структуры канала).

Каналы создаются на heap

### Как работают каналы изнутри
```go
type hchan struct {
    qcount   uint           // количество элементов в буфере;
    dataqsiz uint           // размерность буфера
    buf      unsafe.Pointer // указатель на буфер
    elemsize uint16        // размер элемента в канале
    closed   uint32        // флаг закрытия канала (не bool, так как atomic не работает с bool)
    elemtype *_type       // тип элементов в буфере
    sendx    uint         // индекс tx
    recvx    uint         // индекс rx
    recvq    waitq  // список горутин, ожидающих чтения из канала
    sendq    waitq  // список горутин, ожидающих запись в канала
    lock mutex
}
```

При записи в канал происходит следующее (аналогично при чтении):
1. Структура приобретает блокировку мьютексом;
2. В буфер копируется значение, которое мы положили в канал;
3. Структура освобождается от блокировки мьютексом;

Когда горутина осуществляет попытку записи в канал, буфер которого полон, рантайм переводит эту горутину в состояние “waiting”.
Предположим, что теперь запись возможна, так как другая горутина прочитала данные из канала. Как рантайм узнает, что нужно продолжить выполнение нашей горутины?

```go
// sudog представляет заблокированную горутину, ожидающую чтения или записи
type sudog struct {
    g *g                    // ссылка на горутину
    elem     unsafe.Pointer // данные для записи
    // ...
}
```

В waitq как раз и содержатся заблокированные горутины, которые ожидают чтения/записи. И когда буфер становится доступным для заполнения, происходит следующее:

1. Очередная структура, представляющая ожидающую горутину sudog извлекается из списка waitq;
2. Данные из поля elem добавляются в буфер канала;
3. Горутина из sudog переходит из состояния “waiting” в состояние “runnable” (готова к выполнению).


#### Аксиомы каналов
1. Запись в неинициализированный канал блокирует горутину навсегда
2. Чтение из неинициализированного канала блокирует горутину навсегда
3. Запись в закрытый канал вызывает panic
4. Чтение из закрытого канала возвращает 0 значение
5. Если горутина читает из пустого канала, то она будет заблокирована до тех пор, пока другая горутина не запишет что-то в этот канал.
6. Если горутина пишет в канал, то она будет заблокирована до тех пор, пока другая горутина не прочитает из канала.
