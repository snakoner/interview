Concurrent - параллельно с выполнением программы:

```
1. Mark Start (STW) // GC должен получить консистентный набор корней (roots)
2. Concurrent Mark // окраска
3. Mark Termination (STW) // Пока шёл Concurrent Mark, ссылки менялись. Несмотря на write barrier, нужно удостовериться, что ничего не пропущено
4. Concurrent Sweep // очистка
```

Почему Concurrent sweep безопасен

После завершения Mark Termination у GC есть картина мира:
```
BLACK = оставить
WHITE = удалить
```

Теперь начинается Sweep. Представь, что во время Sweep программа делает:
```
x := &C
```

где C — белый объект, который GC собирается удалить. Но такого не может произойти, потому что на момент начала Sweep: на C уже нет ни одной ссылки из roots

Допустим ситуация:
```
User(black)
Profile(white)

Но в этот момент в программе:
user.profile = Profile

Получается появляется User -> Profile. Но profile - white, то есть подлежит очистке. Поэтому go runtime для присваивании ссылок на объект добавляет writeBarrier(user, profile) -
если profile white
    сделать profile gray

Тогда gc снова посетит profile
```

Инвариант - не должно быть черных объектов, которые указывают на белый.


1. Покрасить все корневые объекты (стек и глобальные переменные) в серый.
2. Выбрать серый объект из набора серых объектов и пометить его как чёрный.
3. Все объекты, на которые указывает чёрный объект, пометить серым. Это гарантирует, что сам объект и объекты, на которые он ссылается, не будут выброшены в мусор.
4. Если в графе остались серые объекты, вернуться к шагу 2.



### Новый Green TEE в GO 1.25

Классический Go GC ходит по графу объектов, то есть он прыгает по указателям. Объекты в heap могут лежать далеко друг от друга в памяти.
```
Root -> Object -> Object -> Object
```

Heap в Go разбит на страницы памяти. Green Tea GC старается выполнять маркировку более локально по страницам heap, чтобы объекты, лежащие рядом в памяти, обрабатывались вместе. Это улучшает cache locality и уменьшает количество cache misses по сравнению с классическим обходом графа объектов, где GC постоянно прыгает по памяти вслед за указателями.
