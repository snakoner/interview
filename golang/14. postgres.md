### JOIN

```
// users
 id | name  |    dept    
----+-------+------------
  1 | Clark | Sales
  2 | Dave  | Accounting
  3 | Ava   | Sales
(3 rows)

// orders
 id | amount | orderedby 
----+--------+-----------
  1 |    100 |         1
  2 |    200 |         1
  3 |    300 |         2
```

```sql
SELECT users.name, orders.amount FROM users <JOIN> orders ON users.id = orders.orderedBy;
```


1. INNER JOIN: Возвращает только те строки, у которых есть совпадения в обеих таблицах.


```
 name  | amount 
-------+--------
 Clark |    100
 Clark |    200
 Dave  |    300

```

2. LEFT JOIN: Возвращает все строки из правой таблицы и совпадающие строки из левой.

```
 name  | amount 
-------+--------
 Clark |    100
 Clark |    200
 Dave  |    300
 Ava   |       
```

3. RIGHT JOIN: Возвращает все строки из правой таблицы и совпадающие строки из левой.

```
 name  | amount 
-------+--------
 Clark |    100
 Clark |    200
 Dave  |    300
```

4. FULL JOIN: Возвращает все строки из обеих таблиц, даже если нет совпадения.
```
 name  | amount 
-------+--------
 Clark |    100
 Clark |    200
 Dave  |    300
 Ava   |       
```

5. CROSS JOIN: декартово произведение

```sql
select users.name, orders.amount from users CROSS JOIN orders;
```

```
 name  | amount 
-------+--------
 Clark |    100
 Dave  |    100
 Ava   |    100
 Clark |    200
 Dave  |    200
 Ava   |    200
 Clark |    300
 Dave  |    300
 Ava   |    300

```

### Индексация

**Индексация в PostgreSQL** – это способ ускорить поиск данных в таблицах, создавая специальные структуры данных (индексы), которые позволяют базе находить записи быстрее, чем при полном сканировании таблицы (последовательное сканирование).

**Индекс** – это структура данных, которая хранит ссылки на строки таблицы, упорядоченные по определенному критерию. Он похож на оглавление в книге: вместо поиска по всей таблице PostgreSQL обращается к индексу и сразу находит нужные данные.

Плюсы:
- Ускоряют SELECT-запросы (поиск, JOIN, фильтрация, сортировка).
- Уменьшают нагрузку на процессор и диск, сокращая число прочитанных страниц.
- Оптимизируют сложные запросы (например, с ORDER BY и WHERE).

Минусы:
- Индексы занимают место в памяти и замедляют вставку (INSERT), обновление (UPDATE) и удаление (DELETE).

Типы индексов:

1. B-Tree (по умолчанию) [Используется в 90% случаев, оптимален для поиска, сортировки, сравнений (=, <, >, BETWEEN).]:

```sql
CREATE INDEX idx_users_email ON users(email);
```

2. Hash-индексы [Быстрее B-Tree, но поддерживают только = ]:

```sql
CREATE INDEX idx_users_hash ON users USING hash(email);
```

3. GIN (Generalized Inverted Index)[Для поиска по JSONB, full-text search, массивам (ARRAY)]

```sql
CREATE INDEX idx_users_tags ON users USING GIN(tags);
```

4. GiST (Generalized Search Tree) [Подходит для поиска по геоданным, расстояниям, JSONB.]

```sql
CREATE INDEX idx_users_location ON users USING GIST(location);
```

5. BRIN (Block Range Index) [Экономит место, быстро работает с огромными таблицами.]

```sql
CREATE INDEX idx_users_brin ON users USING BRIN(created_at);
```


Чтобы проверить, какой тип сканирования выполняется, используйте:

```sql
EXPLAIN ANALYZE SELECT * FROM users WHERE email = 'test@example.com';
```

- Seq Scan (Sequential Scan) → Идет полный перебор строк (⚠ плохо!)
- Index Scan → Используется индекс (✅ хорошо!)
- Index Only Scan → Читаются только индексы, таблица не загружается (🔥 отлично!)


### Блокировки

Блокировки в PostgreSQL используются для управления конкурентным доступом к данным, предотвращая гонки данных (race conditions) и разрушение целостности.




### Шардирование

**Шардирование** (sharding) – это горизонтальное разделение данных на несколько физических узлов для масштабирования PostgreSQL. Это позволяет хранить и обрабатывать огромные объемы данных и распределять нагрузку на несколько серверов.

Плюсы:
- Ускоряет обработку запросов – данные хранятся на разных узлах, и запросы могут выполняться параллельно.
- Распределяет нагрузку – один сервер не перегружается, так как данные делятся между несколькими БД.
- Уменьшает время отклика – ближе к пользователю, если используется геораспределенное шардирование.
- Позволяет хранить больше данных – один сервер больше не является узким местом.

Минусы:
- Сложнее управлять – нужны механизмы балансировки и синхронизации.
- Трудно делать JOIN между шардами – требуется распределенная обработка

#### Способы шардирования в PostgreSQL

1. Manual sharding

Разработчик приложения самостоятельно распределяет данные между несколькими базами.

```go
shardID := userID % 4  // Определяем шард по user_id
dbConn := shards[shardID] // Подключаемся к нужному шарду
```

2. PostgreSQL FDW (Foreign Data Wrapper)

Позволяет размещать разные части таблицы в разных базах и работать с ними как с одной таблицей.

3. PostgreSQL Table Inheritance (Партиционирование + шардирование)

PostgreSQL позволяет разделять таблицу на партиции и хранить их в разных БД.

4. Citus – расширение для распределенных баз

Citus – это распределенная СУБД на основе PostgreSQL, которая автоматически шардирует таблицы и балансирует нагрузку.
