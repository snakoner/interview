Apache Kafka — это распределённая система обмена сообщениями (message broker), используемая для обработки, хранения и передачи потоков данных в реальном времени.

### Основные понятия Kafka:
- Producer (Производитель):
> Отправляет данные (сообщения) в Kafka. Это может быть сервис, логгер, микросервис и т. д.
-  Consumer (Потребитель)
> Читает данные из Kafka и обрабатывает их.
-  Topic (Топик)
> Основная структура хранения сообщений в Kafka.
> - Каждое сообщение принадлежит к определённому топику.
> - Топики могут быть разбиты на партиции (разделы).
- Partition (Партиция)
> - Kafka делит топики на партиции для горизонтального масштабирования.
> - Каждый consumer читает данные из одной или нескольких партиций.
> - Порядок сообщений гарантируется только внутри одной партиции.

- Consumer Group (Группа потребителей)
> - Набор consumer’ов, которые читают данные параллельно.
> - Каждая партиция привязывается к одному consumer’у в группе.
> - Если добавляется новый consumer, Kafka перераспределяет партиции.

- Broker (Брокер):
> Kafka-брокер — это сервер, который:
> - Принимает данные от producer’ов.
> - Хранит сообщения в партициях.
> - Отдаёт данные consumer’ам.

- Zookeeper:
> Kafka использует Zookeeper для управления кластером:
> - Поддерживает информацию о лидерах партиций.
> - Отслеживает состояние брокеров.
> - Контролирует распределение партиций между брокерами.

В новых версиях Kafka Zookeeper можно не использовать (с версией KRaft).

### Как работает Kafka?
1. Producer отправляет данные → Kafka помещает их в нужный топик.
2. Данные распределяются по партициям.
3. Kafka брокеры хранят данные (по умолчанию в течение 7 дней).
4. Consumer читает данные из партиций.
5. Consumer Group управляет балансировкой нагрузки между consumer’ами.

Kafka не удаляет сообщения сразу после обработки. Consumer сам отслеживает, где он остановился (offset).

### Основные фичи Kafka

- ✅ Высокая производительность – Kafka обрабатывает миллионы сообщений в секунду.
- ✅ Горизонтальное масштабирование – можно добавлять брокеры и партиции.
- ✅ Отказоустойчивость – поддерживает репликацию данных.
- ✅ Гарантированный порядок сообщений – в пределах одной партиции.
- ✅ Хранение сообщений – Kafka хранит данные независимо от потребителей.

### Гарантии доставки сообщений

Kafka поддерживает три режима доставки сообщений:

1️⃣ At-most-once (Не более одного раза)
- Сообщение может потеряться, но никогда не будет дублироваться.
- Быстро, но ненадёжно.

2️⃣ At-least-once (Не менее одного раза) (по умолчанию)
- Сообщение может дублироваться, но не потеряется.
- Требуется идемпотентность для обработки дубликатов.

3️⃣ Exactly-once (Ровно один раз) (только с Kafka Streams)
- Гарантирует, что сообщение обработается один раз и только один раз.



## Когда использовать Kafka?

-  Если нужно передавать данные асинхронно
-  Если важна надежная доставка сообщений
-  Если нужна потоковая обработка данных (реальное время)
-  Если требуется хранение истории сообщений
