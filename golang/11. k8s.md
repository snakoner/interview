Kubernetes (K8s) — это система управления контейнерами, которая автоматизирует: 
- деплой
- масштабирование
- управление контейнеризированными приложениями

Kubernetes автоматически распределяет нагрузку между узлами (Nodes).

### Основные концепции Kubernetes
0. Кластер
> Логическое соединение всех узлов.
2. Node (узел)
> Физический или виртуальный сервер, на котором запущены поды.

В кластере выбирается главный узел, который управляет и распределяет нагрузку на рабочие узлы.

На каждом узле запускаются следующие сервисы (в том числе и на главном):
- Container runtime - отвечает за создание и контроль контейнеров на каждом из узлов
- kubelet - коммуникация между разными узлами
- kube-proxy - отвечает за сетевые ресурсы

Кроме того, на главном узле также есть:
- API Server
- Scheduler - планировать и распределять нагрузку
- Kube controll manager - контролирует все поды в кластере

2. Pod

Наименьшая единица в Kubernetes. Под может содержать один или несколько контейнеров, но лучше иметь один контейнер - один под.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-pod
spec:
  containers:
  - name: my-container
    image: nginx
```

```bash
// kubectl apply применяется для создания, обновления и управления ресурсами
// Если ресурс не существует → он создаётся
// Если ресурс уже существует → он обновляется

kubectl apply -f pod.yaml
```

3. Deployment

Обеспечивает автоматическое управление репликами подов:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: nginx
```

```bash
kubectl apply -f deployment.yaml
```

4. Service (Сервис)

В Kubernetes Service (сервис) — это объект, который позволяет организовать доступ к подам (Pods) внутри кластера.

Почему он нужен?
- Поды не имеют постоянных IP-адресов — они могут перезапускаться и получать новые IP.
- Сервис предоставляет стабильный IP и DNS-имя для группы подов.
- Позволяет балансировать нагрузку между подами.


```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: my-app
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
```

```bash
kubectl apply -f service.yaml
```
