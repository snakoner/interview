# Компилятор golang

Рассмотрим программу на C:
```c
#include <stdio.h>

int main() {
  printf("Hello, world!");
}
```

После компиляции размер бинарного файла ~8KB.

Скомпилируем программу на golang:
```golang
package main

import "fmt"

func main() {
  fmt.Println("Hello, world!")
}
```

Размер бинарного файла ~2MB.

Что содержит бинарный файл?

> Runtime GO - код, который выполняется в программе, но который мы сами не вызывали. В него входят:
> 1. Планировщик
> 2. Сборщик мусора
> 3. Аллокатор памяти

> Обширная стандартная библиотека

> Отладочная информация

### Планировщик
Планировщик управляет горутинами. 

Зачем нужны горутины? \
Стандартные потоки ОС тяжелые и медленные. 

Отличие потоков от горутин:
|                |Threads                     |Goroutines|
|--|--|--|
|Управление    |Планировщиком OS            | Планировщиком Go, который входит в рантайм Go
|Объем           |~1-2MB                      | ~2KB
|Переключение контекста|Медленное переключение       |Более быстрое переключение контекста
|Способы взаимодействия|    IPC               |Более быстрые каналы|


`GOMAXPROCS` - максимальное количество тредов OS, по которым планировщик go будет распределять горутины. Ограничен максимальным числом процессорных ядер.

##### Особенности
1. Планировщик вызывает горутины по методу FIFO - по порядку их вызова (go func()).
2. Захват чужой работы - есть какой то поток OS свободен, то он может захватить на выполнение горутины из других тредов.

##### Недостатки
1. Нет контроля над приоритетами горутин
2. Нет гарантии выполнения горутин - нельзя сказать, что горутина точно выполнится через какой-то определенный промежуток времени
3. Если происходит захват чужой работы, то это снижаем эффективность кешей

#### Многозадачность
В go используется неявная кооперативность:
1. При выполнении операций ввода-вывода планировщик go переключает горутины.
2. Явный вызов runtime.Gosched() - редко используется
3. Часто при вызове функции тоже происходит переключение между горутинами(?)
4. В go хотят внести вытесняющую многозадачность, так как горутина, которая например, выполняет какой-то простой цикл, может занять все процессорное время треда OS.
