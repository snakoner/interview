### Типы работы: 

- Preemptive (вытесняющий) - планировщик может прервать горутину, если она слишком долго выполняется 
- Cooperative (кооперативный) - горутины уступают управление сами, вызывая определён точки (syscall, функция рантайма и тд) 

В Го сейчас кооперативно-вытесняющий планировщик - горутины имеют точки проверки, но sysmon насильно прервёт горутину через SIGURG, если горутина работает > 10ms. 


Что делает sysmon. Примерно каждые несколько миллисекунд:

```
sysmon
 |
обходит все P
 |
смотрит кто выполняется слишком долго
```

### Модель
```
G = Goroutine
M = Machine / OS thread
P = Processor / logical execution context
```

P (Processor) — это логический процессор Go runtime. Он хранит очередь goroutine и даёт потоку ОС право выполнять Go-код. Количество P задаётся через GOMAXPROCS и определяет уровень параллелизма Go-программы.
Когда горутина блокируется, то P отцепляется от M и прицепляется к другому.

Количество P задается через GOMAXPROCS.

```
            Global Run Queue
                  |
                  v
        +---------+---------+
        |                   |
       P1                  P2
   local queue         local queue
   G G G G             G G G G
        |                   |
        v                   v
       M1                  M2
   OS thread           OS thread
        |                   |
        v                   v
   executes G          executes G
```

```
runnable  — готова к запуску
running   — сейчас выполняется
waiting   — ждет канал, mutex, timer, I/O
syscall   — находится в системном вызове
dead      — завершилась
```

Горутина может блокироваться:
```
channel
mutex
network I/O
timer
syscall
```

Открепление происходит только при syscall, так как M уже ушел в ядро. При waiting не открепляемся
